# 第 6 章 IP 管理

## 功能概述

IP 管理围绕「网段内的 IP 与 MAC 地址」展开四个子页：**采集任务**（以任务为单位圈定一组设备、设定采集间隔，灵枢自动定时登录这些设备采集整网段 IP-MAC 对照表）、**网段管理**（采集数据实时聚合出的网段视图，查看每网段 IP 使用统计与明细）、**异常检测**（按观测来源与历史绑定比对，自动发现 IP/MAC 异动）、**OUI 管理**（MAC 前缀与厂商对照库）。进入 IP 管理后默认显示「采集任务」子页。

采集是任务制的：一个任务 = 任务名称 + 设备清单 + 自动采集开关 + 独立采集间隔。一台设备只能属于一个采集任务；除自动定时轮外，每行任务还可随时「立即执行」手动触发一轮。网段管理子页的网段不再需要手动登记——采集数据入库后自动按 /24 聚合呈现。

页面结构：顶部一行页签，从左到右为「采集任务 / 网段管理 / 异常检测 / OUI 管理」，每个子页内为各自的工具栏 + 表格（网段管理另有统计卡）。

## 界面布局

四个子页共用「顶部页签 + 工具栏 + 数据表格」的纵向结构：

- 采集任务：一行全局调度栏（ARP 保留天数 + 新建/导出按钮）+ 任务表格（可展开看上轮按设备明细）。
- 网段管理：左右双表布局（左网段视图、右选中网段的统计卡与 IP 明细）。
- 异常检测：统计五卡 + 内层「变更事件 / 排除 IP」页签。
- OUI 管理：统计三卡 + 工具行 + 表格。

## 逐元素详解

### 采集任务子页

功能：创建采集任务圈定一组网关/核心设备（需已配置 SSH 或 Telnet 通道，见 [第 5 章](./05-devices.md)），设定采集间隔后灵枢自动按任务逐台登录设备执行 ARP 表查询命令，把整网段的 IP-MAC 对照数据采集入库，作为网段视图与异常检测的数据源。

| 自动采集 | 开关 | 新建默认开——建任务即意图采集，保存后立即跑首轮 |

| 选择目标设备 | 内嵌平铺设备选择器 | 必选至少一台（校验「请选择至少一台设备」）；顶部「已选 N 台」计数 + 过滤框（占位「搜索设备名称 / IP」，按名称/IP 即时过滤）；设备列表每行为复选框 + 设备名 + IP + 标注 |

设备选择器内的两种标注：

- **已属其他任务的设备**：复选框置灰不可勾，右侧标签「已属「{任务名}」」，悬停提示「一台设备只能属于一个采集任务」。这是选择态主防线；极少数并发窗口漏拦时，保存会失败并原样透出主进程的中文错误（如「设备「X」已属于任务「Y」……」），弹窗不关、输入保留。
- **无 SSH/Telnet 通道的设备**：可以勾选（知情选入），右侧标签「无通道·每轮跳过」，悬停说明每轮记「跳过」不记「失败」。

保存成功提示「任务已创建」/「任务已更新」并关闭弹窗。

**自动调度行为**（无需手动干预的底层规则）：

- 新建任务且自动采集开 → 保存后立即跑首轮，之后按间隔自动循环；下轮时刻 = 本轮开始 + 间隔（采集耗时不吃周期；单轮耗时超过间隔时完成后立即再跑）。
- 系统睡眠唤醒后自动补采错过的轮次（唤醒即补，不用重启应用）。
- 任一轮完成（手动触发/定时轮/唤醒补采）时任务列表自动刷新并弹出完成提示，「正在采集中…」随之消解。
- **失败指数退避**：同一设备连续失败 3 次起进入跳轮保护——跳 2 轮 → 4 轮 → 8 轮封顶，避免对挂死设备反复长等待登录。退避期间每轮只做 TCP 端口探活（3 秒超时，SSH 22 / Telnet 23），**探活成功立即恢复正常采集节奏并入当轮采集**——设备自行恢复后无需任何人工操作，永不永久休眠。

### 网段管理子页

功能：查看采集数据实时聚合出的网段视图与每网段的 IP 使用统计、明细。**网段不再是手动登记的资产表**：采集数据入库后自动按前三段（/24）聚合呈现，本子页没有「添加网段 / 编辑 / 删除 / 自动发现」入口；老版本手动登记的存量行以「手动」标签只读并入。

工具栏从左到右：「导出」（未选网段时禁用；导出选中网段的使用情况 CSV，手动存量行不进导出）、「刷新」（重查网段视图与任务域选项——任务删除等写操作不会自动通知本子页，点它拿最新数据）、右置「任务域」下拉。

**任务域下拉**（筛选数据的来源范围，切换后视图与 IP 明细同步按域重查并回到第 1 页）：

| 选项 | 含义 |
| --- | --- |
| 全部来源（默认） | 不区分来源的全部采集数据 |
| 无任务（手动采集历史） | 仅老版本手动采集（未归属任务）的历史数据 |
| 各任务名 | 仅该任务采集的数据 |

**网段视图表**（左侧约 4 成宽）列：网段（A.B.C.0/24 形态等宽字体）/ IP 数 / 来源设备数 / 归属任务 / 最近观测（「N 分钟前 / N 小时前 / N 天前」三档，悬停绝对时间；无观测显示「—」）/ 操作（仅「查看」，手动存量行同）。

归属任务列三种形态：

- 一个或多个蓝色任务名标签并列——该网段的数据来自这些任务；
- 灰色「无任务历史」标签——只有老版本手动采集的数据；
- 灰色「手动」标签——老版本手动登记的存量行（只读并入，无聚合统计，不受任务域筛选影响）。

点击行任意位置即选中该网段（行高亮）并在右侧加载详情；无任何网段数据时显示空态「暂无网段数据」+「执行采集任务后此处自动呈现网段」。

**右侧详情区**（约 6 成宽）：未选网段时显示「请选择一个网段查看 IP 详情」。选中后依次为：

1. 统计四卡：总IP / 已使用（绿）/ 可用（蓝）/ 使用率（%）。
2. 明细工具行：「搜索 IP」输入框、「搜索 MAC」输入框、「搜索」按钮（输入框内回车同样触发；重查自动回到第 1 页）。
3. 截断提示条（明细超出单次加载上限时出现，见「规则与限制」）。
4. IP 明细表：IP 地址 / MAC 地址 / 厂商 / 状态（「已使用」绿或「弃用」灰）/ 接口 / 来源设备 / 观测时间（三档相对时间，悬停绝对时间），每页 20 条。

**IP 归属判定与多源展开**：明细表每个 IP 恰一行，MAC、接口、来源设备、观测时间取**当前筛选域内该 IP 最新一次观测**（代表行）；「来源设备」即这次观测的采集设备。同一 IP 被多台采集设备观测到时，MAC 列后挂「多源 N」标签（悬停列出「另经 X、Y 观测」的其余来源设备名），该行可展开显示域内**全部观测来源**子表（列：设备 / 接口 / MAC / VLAN / 观测时间），子表上方附一句视角说明：「接口为采集设备上的三层接口（用于定位 IP 所在网段侧），非终端物理口」。单源行无展开控件。

### 异常检测子页

功能：每次采集入库时自动与历史 IP-MAC 绑定比对，记录三类异常事件，供人工确认/排除/导出。

比对按**观测来源各自跟踪**：同一来源设备视角下同一 IP 的 MAC 变化才产生告警；不同采集设备对同一 IP 看到不同 MAC（跨三层路由视角：A 看终端真实 MAC、B 看 A-B 互联口 MAC；VRRP 虚 MAC 与真实 MAC 并存）属拓扑常态，不告警——多源观测在网段管理子页的「多源」展开中各自可见。因此跨三层路由、VRRP 组网的环境不会再出现反复振荡的 MAC 变化误报。

顶部统计五卡：总事件 / 未确认（红色）/ MAC变化 / 新IP / IP重用。

**异常类型**：

| 类型 | 标签颜色 | 含义 |
| --- | --- | --- |
| 新IP（new_ip） | 蓝色 | 网段中首次出现的 IP 地址 |
| MAC变化（mac_changed） | 橙色 | 同一来源设备视角下，同一 IP 的 MAC 与该来源的历史记录不同（可能是换了网卡或存在 ARP 欺骗） |
| IP重用（ip_reused) | 紫色 | 原本弃用的 IP 重新出现 |

子页内两层页签：「变更事件」与「排除 IP」。

**变更事件页签**工具栏从左到右：

| 元素 | 行为 | 规则与限制 |
| --- | --- | --- |
| 「全部确认」 | 一键确认全部未确认事件，提示「已确认 N 条」 | 无未确认事件时禁用 |
| 「删除选中 (N)」红色按钮 | 删除勾选的事件（气泡确认「确定删除选中的事件?」） | 未勾选禁用；提示「已删除」 |
| 「排除选中 IP」 | 把勾选事件的 IP 加入排除规则（不再参与异常检测） | 未勾选禁用；提示「已排除 N 个 IP」 |
| 「导出全部」 | 导出全部变更事件 CSV | — |
| 「导出未确认」 | 仅导出未确认事件 CSV | — |

**变更事件表**列：IP / 类型（彩色标签）/ 原 MAC / 新 MAC / 检测时间 / 状态（「已确认」绿色或「未确认」红色）/ 操作（未确认行有「确认」链接；历史图标按钮打开「IP 绑定历史」弹窗）。每页 20 条，可勾选多行。

**「IP 绑定历史」弹窗**：显示该 IP 历史上绑定过的所有 MAC（列：MAC / 首次发现 / 最后发现 / 状态「活跃」或「非活跃」），用于人工研判 MAC 变化是否正常。

**排除 IP 页签**：工具行「添加排除规则」按钮 + 说明文字「支持 IP、CIDR(192.168.1.0/24)、通配符(192.168.1.*)」。表格列：IP/CIDR / 描述 / 操作（删除，带确认）。添加弹窗两输入框：「IP / CIDR / 通配符」与「描述(可选)」。

### OUI 管理子页

功能：维护 OUI（MAC 地址前 6 位十六进制与网卡厂商的对照表）。系统自带基础库，可自定义扩充；网段明细中的「厂商」列与设备 MAC 识别都依赖它。

顶部统计三卡：总条目 / 自定义 / 厂商数。

工具栏从左到右：

| 元素 | 行为 | 规则与限制 |
| --- | --- | --- |
| 搜索框「搜索 OUI 前缀或厂商名称」 | 输入约 0.3 秒后自动搜索 | 清空恢复全量列表 |
| 「添加」主按钮 | 弹「添加 OUI」表单：OUI 前缀（必填，占位「6位十六进制，如: 001122 或 00:11:22」）、厂商名称（必填） | 成功提示「添加成功」；列表中显示为「自定义」蓝色标签 |
| 「批量导入」 | 弹批量导入窗，多行文本每行「OUI前缀,厂商名称」（如 001122,Huawei） | 无有效行提示「无有效数据」；成功提示「成功导入 N 条」 |

表格列：OUI 前缀（显示为 xx:xx:xx 格式）/ 厂商名称 / 类型（「自定义」蓝标签或「系统」灰标签）/ 操作（编辑；仅自定义条目可删除，系统条目无删除按钮）。每页 20 条。

## 调度与数据保留

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 定时采集 | 任务制：每任务独立间隔 + 任务级自动采集开关 | 没有全局总开关；自动采集开的任务创建后立即跑首轮并按间隔循环；任意任务行内可「立即执行」手动加一轮 |
| 采集间隔 | 60 分钟（新建任务默认，可改 5~1440） | 不同任务可设不同间隔（核心机组每小时、边缘网段每天等） |
| 周期锚定 | 下轮 = 本轮开始 + 间隔 | 采集耗时不算进周期；单轮耗时超过间隔时完成后立即再跑 |
| 睡眠唤醒补采 | 自动 | 系统睡眠唤醒后自动补采错过的轮次 |
| 失败退避 | 连败 3 次起跳轮 2→4→8 封顶 | 退避期 TCP 探活监测，设备恢复响应后立即回到正常节奏（永不永久休眠）；退避只针对设备不可达（登录/执行失败） |
| 数据保留 | 90 天（0=永不删除） | 采集任务子页全局栏设置；超期数据分批自动清理，每个 IP 的最新一条记录永不删除 |
| 采集通道 | SSH / Telnet | 按设备已配置通道执行，两类都有时 SSH 优先于 Telnet；无这两类通道的设备（仅 Web/RDP、仅客户端回连通道的 Windows 主机）每轮记「跳过」不记「失败」 |

## 异常研判指引

| 事件类型 | 常见原因 | 建议动作 |
| --- | --- | --- |
| 新IP | 新设备上线 / 临时接入 / 未登记私接设备 | 核对资产台账：登记了的点「确认」，明确合法；不明来源先排查 |
| MAC变化 | 更换网卡 / 虚拟机迁移 / ARP 欺骗攻击 | 点历史图标看绑定轨迹：单次变更且有人工变更记录则确认；同一来源视角下 MAC 反复跳变需按 ARP 欺骗排查。注意跨采集设备的 MAC 差异（三层互联口 MAC、VRRP 虚 MAC）属拓扑常态，系统不对此告警 |
| IP重用 | DHCP 正常回收再分配 / 静态 IP 被新设备占用 | 核对新占用设备身份；确属正常则确认，反复异常则检查地址规划 |
| 噪声型 IP（打印机、访客 Wi-Fi 等） | 动态性强的地址天然频发事件 | 勾选后「排除选中 IP」加入排除规则 |

## 典型操作流程：从零建立 IP 监控

1. 在 [第 5 章](./05-devices.md) 添加网关设备（如「核心交换机-01」，192.0.2.1 为示例），配置 SSH 通道凭证。预期测试连接通过。
2. 切到 IP 管理 → 采集任务子页，点「新建采集任务」：填名称「核心机组」、间隔保持 60 分钟、在设备选择器勾选刚加的设备，点「创建任务」。预期任务出现在列表且立即开始首轮（下轮列显示「正在采集中…」），完成后弹出「任务「核心机组」采集完成：成功 1 / 失败 0 / 跳过 0」。
3. 展开该任务行。预期看到上轮按设备明细：设备名、IP、绿色「成功」标签、ARP 条目数与耗时。
4. 切到网段管理子页。预期左侧自动出现采集数据聚合出的 /24 网段行（IP 数、来源设备数、归属任务蓝色标签、最近观测）；点击某行，右侧出现统计四卡与 IP 明细表。
5. 需要按任务看数据时，用右上「任务域」下拉切换到对应任务名；发现数据与任务操作不同步时点「刷新」。
6. 等待下一次自动轮（或回采集任务行内点「立即执行」）后，切到异常检测子页。预期统计卡出现事件计数（首轮采集只建基线，第二轮起才产生异常）。
7. 逐条研判变更事件：正常的变更点「确认」；已知良性且不想再报的 IP 勾选后点「排除选中 IP」；拿不准的点历史图标看该 IP 的 MAC 绑定轨迹。

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 设备归属唯一 | 一台设备只能属于一个采集任务：设备选择器置灰拦截 + 保存时兜底校验（并发窗口漏拦时报中文错误且不落半条数据） |
| 采集数据写入 | 单设备单事务：一台失败只回滚该设备，同轮已成功设备的数据保留 |
| 删除连带 | 删除任务会分批删除该任务采集的全部 ARP 历史与运行记录，不可恢复；删除确认气泡中实时显示波及条数 |
| 首次基线 | 全新环境的第一次采集只建基线不报异常；从第二次采集起开始比对产生异常事件 |
| 排除规则生效 | 加入排除清单的 IP/CIDR 不再产生异常事件（已产生的不追溯删除） |
| 数据保留 | ARP 数据按保留天数自动清理（默认 90 天，0=永不删除；每 IP 至少保留最新一条永不删）；清理分批进行不卡界面 |
| 网段视图口径 | 网段按采集数据前三段（/24）聚合；老版本手动登记行只读并入且不参与任务域筛选与导出 |
| 单次加载上限 | 网段 IP 明细默认上限 2000 条、OUI 默认 5000 条、异常事件默认 100 条，超出显示截断提示条并可用 CSV 导出获取全量 |
| 导出格式 | 全部导出为 CSV 文件（带 BOM，Excel/WPS 可直接打开），导出后提示保存路径 |
| OUI 删除保护 | 系统内置条目不可删除，仅自定义条目可删改 |
| IPv4 only | 网段与 IP 计算仅支持 IPv4 |

## 数据流转说明

四个子页共享同一份采集数据，理解流转关系有助于定位问题：

```
采集任务（数据入口：定时轮 / 行内立即执行 / 睡眠唤醒补采）
        │  逐台登录设备执行 ARP 查询，单设备单事务入库（附任务与来源设备归属）
        ▼
ARP 观测数据
        ├──► 网段管理（按 /24 实时聚合出网段视图；明细取筛选域内最新观测代表行，多源可展开）
        ├──► 异常检测（按观测来源各自与历史绑定比对产生变更事件）
        │         └──► 排除 IP（人工屏蔽噪声）
        └──► 保留清理（到期分批删旧，每 IP 最新一条永留）

OUI 管理（独立基础库）◄── 供网段明细「厂商」列识别
```

- 网段的「已使用」口径来自 ARP 采集数据，不是主动扫描；IP 状态的「弃用」按来源所属任务的节奏判定（连续 2 倍间隔未见该 IP 才标弃用，无任务归属的按 24 小时），多任务轮次交错也不会把他任务刚更新的新鲜 IP 误判为弃用。
- 异常事件在每次采集入库时自动产生，无需手动触发检测。
- OUI 库更新（新增自定义条目）后，明细中的厂商列在下次加载时按新库识别。

## 网段明细字段说明

| 字段 | 含义 |
| --- | --- |
| IP 地址 | 网段内出现的 IPv4 地址（每 IP 恰一行） |
| MAC 地址 | 该 IP 当前绑定的 MAC——当前筛选域内最新一次观测的值；多源时后挂「多源 N」标签 |
| 厂商 | 按 OUI 库识别的网卡厂商（识别不到为空） |
| 状态 | 已使用（近期仍被采集到）/ 弃用（超过来源任务节奏 2 倍间隔未再观测到；之后再被采集到会自动恢复为已使用） |
| 接口 | 代表行来源设备上记录该表项的接口名（三层接口，见展开区说明） |
| 来源设备 | 采集到代表行的设备（域内最新观测的来源） |
| 观测时间 | 代表行的采集时刻（相对时间显示，悬停看绝对时间） |
| 多源 N（展开） | 该 IP 在域内的全部观测来源：各来源设备、接口、MAC、VLAN 与各自观测时间 |

## 常见问题

**Q1：任务行展开里某设备一直显示金色「退避中」？**
该设备连续失败 3 次以上，进入了自动跳轮保护——灵枢不再反复登录它，只做轻量 TCP 探活；设备恢复响应后会自动回到正常采集节奏，无需任何操作。悬停标签可看到「连续失败 N 次，已跳 M 轮」全句。长期退避通常意味着凭证错误或网络不通，到 [第 5 章](./05-devices.md) 修正该设备通道后即自愈。

**Q2：删除任务后网段列表没变化？**
网段视图随采集数据实时聚合，但任务删除不会自动通知网段子页刷新——点工具栏「刷新」即可拿到最新视图与任务域选项。

**Q3：明明换了设备网卡，怎么不再报 MAC 变化？**
两种可能：该 IP 已被加入排除规则（到「排除 IP」页签检查删除）；或者 MAC 差异只出现在不同采集设备之间（跨三层路由视角、VRRP 虚 MAC）——这是拓扑常态，系统按观测来源各自跟踪，只对同一来源视角下的变化告警，属正常行为不是漏报。

**Q4：网段统计的「已使用」是什么口径？**
以 ARP 采集数据为准：近期仍被采集到的 IP 计为已使用。「近期」按该 IP 来源所属任务的采集节奏判定（2 倍间隔），不是全局固定窗口。

**Q5：列表上方黄色「已显示前 N 条」提示影响我找目标数据？**
这是单次加载上限的保护。用搜索框（IP/MAC/厂商/OUI 关键词）缩小范围，或点「导出」拿全量 CSV 离线分析。

**Q6：想批量补充公司自有设备的厂商对照？**
用 OUI 管理的「批量导入」，每行「OUI前缀,厂商名称」粘贴多行一次导入。

**Q7：为什么第一次采集后异常检测里什么都没有？**
首次采集只建立基线（记录现状），从第二次采集起才会与基线比对产生「新IP / MAC变化 / IP重用」事件。

**Q8：导出的 CSV 文件在哪？**
导出时弹出系统保存对话框，文件名已预填（如 arp-table-20260913.csv、network-usage-…、ip-mac-changes-…），保存位置由你在对话框中选择（初始目录由系统决定，Windows 通常停留在上次使用的目录）；导出成功提示中包含完整保存路径。CSV 可用 Excel/WPS 直接打开。

**Q9：多台设备都能采到同一网段的 ARP，会重复计数吗？**
不会。网段明细每个 IP 恰一行，取筛选域内最新观测为代表；多源观测通过「多源 N」标签与行展开完整可见，异常检测也按来源各自跟踪，不会因多源视角差异反复告警。

**Q10：没有 SSH/Telnet 通道的设备能放进采集任务吗？**
能勾选（标注「无通道·每轮跳过」），每轮采集记「跳过」不记「失败」。仅客户端回连通道纳管的 Windows 主机无法执行 ARP 查询命令，放入任务只会累积跳过记录，建议不选。

**Q11：「下轮」列显示「—」是什么意思？**
该任务的自动采集开关是关的，不会自动排轮。打开行内「自动采集」开关即恢复调度；关闭期间仍可「立即执行」手动采集。

**Q12：系统睡眠一段时间后数据会断档吗？**
不会。唤醒后灵枢自动补采错过的轮次；错过多个周期时补一轮后按新节奏继续（不重放历史轮次）。

**Q13：网段还能手动添加吗？**
本版本网段是采集数据的实时聚合视图，不再支持手动登记与编辑；老版本登记的手动网段以「手动」标签只读保留（可查看，不参与任务域筛选与导出）。想监控一个新网段，把覆盖它的设备加入采集任务即可。

**Q14：保留天数设成 0 会怎样？**
0 是合法特殊值「永不删除」——所有 ARP 历史永久保留，库体积会持续增长；需要控制体积时改回具体天数（到期自动清理，每 IP 最新一条永不删）。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 采集任务 | 定时采集的管理单位：任务名称 + 设备清单 + 自动采集开关 + 独立采集间隔；一台设备只能属于一个任务 |
| 采集间隔 | 任务相邻两轮采集的间隔分钟数（5~1440，默认 60） |
| 轮（采集轮） | 一次对任务内全部设备的完整采集过程；每轮按设备记录成功/失败/跳过明细 |
| 跳过 | 任务内无 SSH/Telnet 通道的设备每轮的记录形态——不计失败、不尝试登录 |
| 退避 | 设备连续失败 3 次起的自动跳轮保护（2→4→8 轮封顶），期间仅 TCP 探活，恢复即回正常节奏 |
| TCP 探活 | 不登录设备、只测采集端口（SSH 22 / Telnet 23）能否连通的轻量探测（3 秒超时） |
| 唤醒补采 | 系统睡眠唤醒后自动补采错过的采集轮次 |
| ARP 表 | 设备上 IP 与 MAC 地址的对照缓存表，是采集的数据源 |
| 网段 | 采集数据按前三段（/24）聚合出的地址范围（如 192.0.2.0/24），统计与检测的单位 |
| 任务域 | 网段管理子页按数据来源筛选的范围：全部来源 / 无任务（手动采集历史）/ 指定任务 |
| 观测 | 一次采集中某来源设备看到了某 IP-MAC 表目；「观测时间」即该次采集时刻 |
| 多源 | 同一 IP 被多台采集设备观测到；明细以最新观测为代表行，展开可看全部来源 |
| 来源设备 | 采集到某条数据的设备（网关/核心设备，而非终端） |
| 基线 | 第一次采集建立的历史参照，之后采集与它比对产生异常 |
| 新IP | 网段中首次出现的 IP 地址（异常类型之一） |
| MAC 变化 | 同一来源视角下同一 IP 关联的 MAC 改变（换网卡或 ARP 欺骗的信号） |
| IP 重用 | 已弃用的 IP 重新上线（异常类型之一） |
| 排除规则 | 按 IP / CIDR / 通配符排除的对象，不再参与异常检测 |
| OUI | MAC 地址前 6 位十六进制厂商编号段 |
| 通配符 | 形如 192.168.1.* 的范围表达，星号匹配任意值 |
| 弃用 IP | 历史出现过、超过来源任务节奏 2 倍间隔未再观测到的 IP |
| 保留策略 | 采集数据自动清理的期限规则（默认 90 天，0=永不删除） |
| 截断提示条 | 表格数据超出单次加载上限时顶部显示「已显示前 N 条 / 共 M 条」的黄色提示条（底层数据层以分页信封控制单次返回量） |
