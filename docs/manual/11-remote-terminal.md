# 第 11 章 远程终端

## 功能概述

远程终端覆盖从灵枢连到设备的全部四类通道：SSH 终端（独立窗口）、Telnet 终端（独立窗口）、Web 界面（系统浏览器）、RDP 远程桌面（.rdp 文件调用）。连接入口有两处：拓扑页双击节点，与右侧详情栏登录通道区的行内「连接」按钮（见 [第 4 章](./04-topology.md)）；本章说明通道行为与终端窗口本身的操作。Windows 主机托管资产不走这四类登录通道——其 command_executor 任务通道无交互终端，命令入口为「执行命令」弹窗（见下文「Windows 主机（托管资产）」与 [第 5 章](./05-devices.md)）。

## 界面布局

SSH/Telnet 连接会打开一个独立终端窗口（约 900×600 像素，可调整）：窗口标题为「终端 - {设备名} ({IP})」，无菜单栏；窗口内是黑底终端界面（等宽字体、闪烁光标、自动适配窗口大小）。可同时打开多个终端窗口连多台设备，互不干扰。

Web 与 RDP 不开终端窗口：Web 直接调起系统默认浏览器打开设备管理页；RDP 生成连接文件并调起 Windows 自带的远程桌面客户端 mstsc。

## 逐元素详解

### 通道选择

双击拓扑节点时按设备通道配置自动分流（详见第 4 章「双击连接三分支」；可直连通道只数 SSH/Telnet/Web/RDP 四类，Windows 主机的 command_executor 任务通道不计入）：单通道直连；多通道弹选择框（每行显示通道名 + 登录描述如 `admin@192.0.2.1:22`，上次用过的通道带「上次使用」徽标并预选；配了任务通道的 Windows 主机在选择框底部另有一行静态展示 `command_executor @{识别码}`，带「任务通道」徽标，仅展示不可选、不参与记忆）；零通道引导去补凭证（仅配任务通道的 Windows 主机同样落此分支，提示改为可补配 RDP 远程桌面）。未指定通道的内部调用（如 AI 执行命令）按「默认通道优先、命令行通道回退」规则解析，命令行回退序为 SSH > Telnet > command_executor（纯 Windows 主机命中任务通道，见第 7 章）。

### SSH 终端窗口

| 特性 | 说明 |
| --- | --- |
| 认证方式 | 密码或密钥（密钥文件路径 / 粘贴密钥内容，二者填一时密钥优先） |
| 连接成功提示 | 终端首行显示「已连接到 {设备名} ({IP})」 |
| 交互 | 完整交互式 shell（xterm-256color，初始 80×24），支持 vim/top 等全屏程序 |
| 编码 | 自动识别设备输出编码（含 GBK 中文设备），防乱码 |
| 超时 | 建连超时 30 秒（慢设备可等待），超时在窗口内显示连接错误 |
| 算法兼容 | SSH 算法列表做最大化兼容（含老设备的传统算法与现代算法） |
| 主机密钥校验 | 首次连接静默记录设备指纹（无弹窗），此后每次连接自动比对；指纹变更时弹警告框人工确认（见下节） |
| 关闭窗口 | 直接点窗口 × 即断开会话（无确认） |
| 异常断开 | 终端显示「连接已关闭」；连接错误显示「连接错误: {原因}」 |

### SSH 主机密钥指纹校验

灵枢对每条 SSH 连接做主机密钥指纹校验，防止连接链路被「中间人」窃听凭证（中间人攻击即有人或程序冒充设备截获你输入的账号密码；Telnet/Web/RDP 通道无此机制）：

- **首次连接**：静默记录该设备的主机密钥指纹（按 IP + 端口记载）并直接连接，无弹窗、无打扰——这种「首次使用即信任」策略称 TOFU。
- **指纹一致**：正常连接，无任何感知。
- **指纹变更**（设备重配、换板、IP 被其他设备复用，或链路真的被劫持）：终端窗口上弹出系统警告框——标题「主机密钥指纹已变更」，正文「主机密钥指纹已变更——可能存在中间人攻击或设备重配，请核对新旧指纹」，明细逐行列出「旧指纹（SHA256）」与「新指纹（SHA256）」。两个按钮：
  - **「信任新指纹并继续」**：核实变更确属设备自身后点选——新指纹替换旧记录并继续本次连接；
  - **「取消」**（默认选中，直接回车即取消）：本次不连接、已记录指纹不变，终端显示「连接错误: 连接已取消：未信任新主机密钥指纹（记录未变更，下次连接将再次确认）」；下次连接会再次弹出比对，不会永久锁死。
- 警告框超过约 30 秒未处理，本次连接会因建连超时失败（指纹记录不变），重新连接可再次确认。

指纹确认**只能在终端连接时进行**：测试连接、AI 执行命令与配置快照、ARP 采集等后台无人值守路径遇到指纹变更不会弹窗，直接失败并提示「主机密钥指纹已变更，请先通过终端连接该设备并确认新指纹」——到拓扑页双击该设备走一次终端连接、确认新指纹后，各后台功能即恢复。

灵枢没有独立的「已知主机管理」界面，指纹记录只随上述确认流程自动更新；设备正常重配后确认一次即长期有效。

### Telnet 终端窗口

与 SSH 终端窗口同形态（黑底 xterm）。差异：明文协议（无加密），默认端口 23；无密钥概念，仅账号密码。同样关闭窗口即断开。

### Web 通道

连接时以系统默认浏览器打开设备配置的 Web URL。浏览器由系统管理（书签/密码填充等用浏览器自己的机制），灵枢不代理其流量。URL 在设备表单 Web 通道页签配置（如 `https://192.0.2.1`）。

### RDP 远程桌面

连接时生成 .rdp 连接文件并调起远程桌面客户端：

| 特性 | 说明 |
| --- | --- |
| 账号 | .rdp 中预填设备配置的用户名；**密码不写入文件**（格式安全限制），由远程桌面客户端自行提示输入 |
| 分辨率 | 设备配置的「分辨率」字段（格式 宽x高，如 1920x1080）写入连接参数；未配置或格式不符使用客户端默认 |
| 端口 | 默认 3389，可在设备配置修改 |
| 会话 | 每次连接生成新连接文件调用；断开由远程桌面客户端自己管理 |
| 启动失败 | 远程桌面客户端调起失败时灵枢不弹错、不崩溃：远程桌面窗口未弹出即调起失败，原因写入主进程日志；临时连接文件无论调起成败都在客户端退出后自动清理 |

### Windows 主机（托管资产）

Windows 主机经客户端回连纳管（见 [第 5 章](./05-devices.md)），绑定的 command_executor 是任务型持久通道：无端口、无交互终端，**不经本章四类登录通道连接**，也不会打开终端窗口。各接触面形态：

| 面 | 形态 |
| --- | --- |
| 详情栏登录通道区 | 任务通道行显示「command_executor ✓ 已托管」并随附 在线/离线/长期离线 状态（悬停可见最近在线时间）；该行**无「连接」按钮** |
| 命令入口 | 详情栏快捷操作区末位「执行命令」按钮（仅 Windows 主机出现；主机离线时禁用，悬停提示「主机离线，无法执行命令」）——打开三段式执行命令弹窗（输入/执行中/终态，用法见 [第 5 章](./05-devices.md)）；主机列表页操作列有同款入口 |
| 终端/桌面连接 | 任务通道不支持终端连接，后台对其显式拒绝；需要图形化操作时给主机补配 RDP 通道，之后走本章 RDP 远程桌面 |
| 测试连接 | 只探测四类传统登录通道，任务通道无探活语义（仅配任务通道的主机测得「未配置登录通道」） |

执行命令弹窗中的命令在执行前按 Windows 命令白名单与黑名单校验（见 [第 10 章](./10-settings.md)），越界直接拒绝并提示原因；每次执行（含中途放弃查看）都记入日志审计（见 [第 9 章](./09-log-audit.md)）。AI 也可经任务通道对在线 Windows 主机执行命令（见 [第 7 章](./07-ai-assistant.md)）。

### 终端窗口通用操作

| 操作 | 方式 | 行为 |
| --- | --- | --- |
| 输入命令 | 直接键入 | 实时发送到设备（与真实终端一致） |
| 复制 | 选中文本后按 Ctrl+Insert | 复制选中内容（终端无右键复制菜单，复制粘贴走浏览器原生剪贴板行为：Ctrl+Insert 是 Windows 传统复制键，此处即可复制；Ctrl+C 保留为向设备发中断信号，不用于复制） |
| 粘贴 | 按 Ctrl+Shift+V | 粘贴到终端（无右键粘贴菜单：Ctrl+Shift+V 是浏览器原生纯文本粘贴键，此处即可粘贴；Ctrl+V 不粘贴——会被当作控制字符发给设备。注意粘贴多行命令会逐行执行） |
| 调整窗口 | 拖动窗口边框 | 终端内容自动重新适配行列数 |
| 多窗口 | 重复连接不同设备（或同设备） | 每个连接独立窗口独立会话 |
| 断开 | 关闭窗口 | 立即断开会话并释放连接 |

### 会话与窗口关联

每个终端窗口与一个设备会话绑定（窗口与会话一一对应）；关闭窗口即断开对应会话，不会影响其他窗口。重启应用或重启安装更新会断开全部远程会话（升级弹窗有专门警告，见 [第 12 章](./12-update.md)）。

## 典型操作流程：连上一台交换机的命令行

1. 确认设备已配置 SSH 通道并「测试连接」通过（见 [第 5 章](./05-devices.md)）。
2. 在拓扑页双击该设备节点。预期：单通道直接弹出终端窗口；多通道先弹选择框（选 SSH，点「连 接」）。
3. 终端窗口出现「已连接到 {设备名} ({IP})」，随后出现设备登录后的提示符（如 `<HW-SW>`）。
4. 像普通终端一样输入命令操作设备；需要粘贴配置时注意多行粘贴会逐行执行。
5. 用完直接点窗口 × 关闭。预期窗口关闭、会话断开，无确认弹窗。

## 典型操作流程：打开设备的 Web 管理页

1. 设备 Web 通道已配置 URL（如 `https://192.0.2.1`，示例地址）。
2. 双击拓扑节点并在选择框选「Web 界面」。预期系统默认浏览器打开该地址。
3. 后续登录与操作在浏览器内完成，与灵枢无关（灵枢只负责安全地打开链接）。

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 通道配置前提 | 连接前设备须已配置对应通道凭证；零通道设备双击会引导补配而非报错 |
| 凭证安全 | 凭证从加密库解密后仅在后台内存中使用，终端窗口与界面不回显明文密码 |
| 上次使用记忆 | 多通道选择框按设备记忆上次所选通道（仅预选增强，可随时改选；记忆只覆盖四类可直连通道） |
| SSH 密钥优先 | 同时配置密码与密钥时密钥优先 |
| SSH 主机密钥校验 | 首连静默记录指纹（TOFU）；指纹变更须在终端连接时人工确认，取消则本次不连、记录不变；无人值守路径（测试连接/AI 执行/配置快照/ARP 采集）遇变更直接失败，须先经终端连接确认 |
| RDP 密码 | 出于 .rdp 格式安全限制不写明文密码，连接时由客户端提示输入（设备表单中的 RDP 密码为预留加密存储字段） |
| Web 外部打开 | Web 通道经安全外链通道调起系统浏览器，URL 协议受白名单约束 |
| 终端独立进程域 | 终端窗口与主窗口隔离注入（终端窗口拿不到主界面的接口通道） |
| 任务通道不直连 | Windows 主机的 command_executor 为任务型托管通道，无交互终端：终端连接入口对其不可用，命令统一经「执行命令」弹窗下发并受 Windows 词表校验 |
| 并发会话 | 多终端并发互不影响；同一设备可开多个会话 |

## 常见问题

**Q1：终端窗口一闪就没了 / 显示连接错误？**
常见原因：凭证错误、设备不可达、端口不对。先到设备管理页点「测试连接」定位（多通道设备会逐通道给出结果），修正后重连。

**Q2：终端里中文乱码？**
SSH 终端自动做编码识别（优先按国际通用的 UTF-8 编码，无法解析时回退 GBK）；Telnet 终端固定按 GBK 解码。若仍乱码，多为设备侧配置的语言环境所致，可在设备上执行显示语言设置类命令修正。

**Q3：双击设备弹出的是浏览器/远程桌面而不是终端？**
那是该设备唯一配置的通道是 Web 或 RDP。要命令行终端，给设备加配 SSH 或 Telnet 通道（第 5 章），双击多通道时会出现选择框。

**Q4：RDP 连接每次都要输密码，能记住吗？**
不能由灵枢代记（.rdp 明文密码行存在安全限制）。可在远程桌面客户端自己的机制中保存凭据。

**Q5：粘贴一段配置为什么直接执行了一半？**
终端粘贴即输入：多行内容会连同回车一起逐行发送。粘贴配置前建议先进入设备的配置编辑模式，或使用设备提供的粘贴缓冲机制。

**Q6：关掉灵枢主窗口，终端窗口还在吗？**
终端是独立窗口，主窗口最小化不影响；退出灵枢应用则会一并断开全部远程会话（含 MCP 工具连接）。

**Q7：能同时给一台设备开两个 SSH 会话吗？**
可以。重复双击设备节点再选 SSH 即可，两个终端窗口两个独立会话。

**Q8：终端字体大小能调吗？**
当前版本未提供界面内字号设置；可通过系统级 DPI 缩放间接影响终端窗口显示大小。

**Q9：为什么 AI 执行命令和我手动开终端互不干扰？**
两者各自建立独立会话（AI 执行链路的通道按「默认通道优先命令行通道」解析，见第 7 章），会话与窗口一一对应隔离管理。

**Q10：Windows 主机为什么没有「连接」按钮，双击弹的是补配表单？**
托管主机绑定的 command_executor 是任务通道，无交互终端、不计入双击可直连通道。对它执行命令用详情栏快捷操作区的「执行命令」（主机在线才可用，见第 5 章）；要图形化桌面操作，补配 RDP 通道后双击即连。

**Q11：连 SSH 时弹出「主机密钥指纹已变更」警告框怎么办？**
说明该设备的主机密钥与上次记录不一致：多数是设备重配、换板或 IP 被复用，少数情况是链路被劫持（中间人攻击）。能核实时（如经设备 Console 口或管理员确认新指纹）点「信任新指纹并继续」；不确定就点「取消」，查清后再连——取消不改记录，下次连接会再弹比对。首次连接不弹任何确认（首连静默记录、自动信任），只有指纹「变化」才需人工确认。测试连接或 AI 执行报「主机密钥指纹已变更，请先通过终端连接该设备并确认新指纹」时同理：先双击设备走终端连接确认一次。
