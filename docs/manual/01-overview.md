# 第 1 章 产品概述

## 灵枢是什么

灵枢（LinkPivot，本项目英文名）是一个运行在 Windows 上的网络拓扑管理桌面工具，面向运维人员。它把日常网络运维中分散在多个工具里的工作收进一个应用：

- **看得见拓扑**：以可视化画布呈现网络设备与它们之间的连接关系，支持自动发现与自动布局。
- **连得上设备**：在同一界面里远程连接并操控设备，支持 SSH / Telnet / Web / RDP 四类远程通道；Windows 机器还可安装客户端自动回连受管（托管资产）。
- **有 AI 辅助**：内置 AI 助手，能读取你授权的知识库与经验库资料、在黑白名单与执行态约束下执行运维命令，把长任务立为多步任务持续推进（应用重启后可一键续行）、把批量设备巡检派发给隔离子代理并行执行，把有价值的对话沉淀成可复用的经验条目，还能生成 Word/Excel 报告文档。
- **管得住资料**：设备台账、运维知识库、经验库、IP/MAC 监控数据全部存在本机数据库中。

灵枢是单机桌面软件（基于 Electron 技术构建，即用一个浏览器内核包装的本地应用），不依赖服务端部署：设备台账、凭证、知识库等数据全部存在本机，不上传云端。联网外发只有两处：使用 AI 助手时——对话内容与检索到的资料片段会发送到你在系统设置中配置的 AI 模型服务商完成推理（知识库文档的图片识别同样发往该服务商的视觉模型）；以及你配置了 HTTP 传输类型的 MCP 服务器时——灵枢会按其配置地址联网调用该服务器。

## 核心概念

以下概念贯穿全手册，首次出现处均给出通俗解释。

### 设备

设备是灵枢里一切管理对象的统称：交换机、路由器、防火墙、服务器等。每台设备有一条台账记录（名称、设备类型、IP 地址、厂商、型号、版本等），以及若干远程通道凭证（见下）。界面上的拓扑节点就是设备。

### 拓扑

拓扑指网络设备之间「谁连着谁」的关系图。灵枢用画布（基于 React Flow 图形库渲染，支持缩放、拖拽、框选的交互式图形区域）呈现：一台设备是一个节点，一条连接关系是一条连线，连线上可标注接口名称。点选设备节点或连线时，画布右侧会自动展开详情栏，用于查看与编辑对应资料（详见 [第 4 章 拓扑管理](./04-topology.md)）。拓扑可以从空白手动搭建，也可以通过「自动发现」功能登录到一台设备上采集邻居信息后自动生成。

### 远程通道

远程通道指灵枢连到一台设备所用的协议方式，共四类：

| 通道 | 说明 | 典型用途 |
| --- | --- | --- |
| SSH | 加密的命令行登录（支持密钥与密码两种认证方式） | 交换机/路由器/Linux 主机命令行 |
| Telnet | 明文的命令行登录 | 只支持 Telnet 的老旧设备 |
| Web | 用系统浏览器打开设备管理页面 | 网页管理的设备 |
| RDP | Windows 远程桌面（生成 .rdp 连接文件并调起系统自带远程桌面客户端 mstsc） | Windows 服务器图形界面 |

一台设备可以同时配置多类通道（例如既有 SSH 又有 Web），连接时再选择用哪一类。详见 [第 11 章 远程终端](./11-remote-terminal.md)。

### AI 助手

AI 助手是一个对话式运维助手。它的工作方式是「分档预取 + 受控执行」：

- **分档预取**：AI 按你提问的内容自动归入四档之一（故障排查 / 配置查询 / 知识问答 / 巡检执行），回答前按档位先检索知识库文档、经验库条目、设备实时数据，把检索到的内容作为上下文再作答；检索到的来源会以徽章形式展示，点击可回查来源明细与设备详情。（预取默认关闭，可在 AI 助手页输入行首齿轮「检索设置」中开启，见第 7 章）
- **受控执行**：会话分两档执行态——默认 plan 态只读调查（只执行只读命令，变更操作以文本方案输出），切换到执行态后 AI 才真正执行变更命令；命令执行前依次过黑名单硬拒（任何情况拒绝）、设备级策略、全局免确认词表与执行模式（每次确认 / 智能 / 全自动）分派、越权强制人工确认。
- **多步任务与批量巡检**：一句「把这批设备的固件版本巡一遍」式的长任务，AI 可立为带步骤清单的多步任务持续推进——界面用任务进度卡呈现目标、步骤与轮次，应用重启后点「继续」一键续行；多台设备的批量巡检会派发给相互隔离的子代理并行执行，每台设备在独立子会话中只读采集，对话里只收到每台设备的结构化摘要，单台失败不影响其余设备（见第 7 章）。
- **上下文可控**：对话区常驻 token 状态栏（模型名、上下文占用比例、用量），长对话可点「手动压缩」即时压缩，上下文接近窗口上限时也会自动压缩——压缩后旧消息退出 AI 上下文，但界面上仍完整保留可查（见第 7 章）。
- **经验起草**：一次有价值的对话可以一键发起「经验总结」，AI 起草经验条目，经你人工确认后进入经验库，下次遇到同类问题可直接复用。

详见 [第 7 章 AI 助手](./07-ai-assistant.md)。

### 知识库

知识库用于管理运维文档：支持导入 PDF / DOCX 等格式，入库后自动解析成章节文本块；检索时把全库章节目录（含摘要）交给 AI 挑选最相关的片段，AI 回答问题或你在界面上检索时都基于这一机制命中内容（详见 [第 8 章 知识库](./08-knowledge-base.md)）。支持图片识别（对文档中的图片做多模态识别，生成文字描述后同样可检索）。

### 经验库

经验库是知识库的一个子页，存放结构化的运维经验条目：适用设备、故障现象、处理步骤、严重级别、标签等。经验条目两个来源：手动新建，或由 AI 从对话中起草后经人工确认发布。经验条目有生效/失效状态与「最后验证时间」，AI 复用一条经验前会校验其是否仍有效。

### IP 监控

IP 监控围绕「网段内的 IP 与 MAC 地址」展开：先在「网段」子页登记你要关注的 CIDR 网段（形如 192.0.2.0/24 的地址段），再通过 ARP 采集（ARP 是设备用来把 IP 地址映射到 MAC 地址的网络协议，登录到网关设备上执行 arp 相关命令即可拿到整网段的 IP-MAC 对照表）周期性或手动采集数据，系统对比历史数据自动发现异常（新出现的 IP、IP 换了 MAC、弃用的 IP 重新出现等），并可按 OUI（IEEE 分配给网卡厂商的编号段，可据此识别网卡厂商）识别设备厂商。

## 安全机制通俗说明

灵枢的安全设计围绕两件事：**凭证不泄露**、**命令不乱跑**。

### 凭证加密存储

你在设备表单里填写的 SSH/Telnet 密码、RDP 密码等敏感信息，不会以明文存进数据库，而是逐字段用 AES-256-GCM 加密（一种业界标准的高强度加密算法，可以理解为给每个字段配一个只有本机能打开的保险箱）后再落库。界面上回显时只显示「已存 ****尾4」这样的脱敏形式——永远看不到完整密码。

### 主密钥绑定机器

所有加密字段共用一把主密钥（masterKey）。主密钥本身落盘时又经 Windows DPAPI（Windows 系统提供的、与当前用户账户绑定的加密保管机制）保护。效果是：**把数据库文件和密钥文件拷到别的电脑、或换一个 Windows 账户打开，都无法解密你的凭证**。因此在做整机迁移/备份时，需要连同用户数据目录一起迁移（见第 2 章「数据存放位置」）。

### IPC 鉴权

界面（渲染进程）与后台（主进程）之间的每一个内部接口调用都经过登录态校验：未登录状态下，除登录/初始化相关的少量接口外全部拒绝。接口报错时返回给界面的错误信息会自动脱敏，不泄露 SQL 语句、磁盘路径等内部细节。

### 命令黑白名单与执行态

AI 或远程执行链路里出现的每一条命令，执行前都必须通过命令安全校验：先拦截分隔符注入（防 `show && rm` 类拼接绕过），再比对**黑名单**首词——黑名单是一组内置的危险命令首词（覆盖关机重启、进入配置模式、删除覆写、路由与安全策略变更类高危操作），任何执行模式、任何执行态下一律直接拒绝；内置词只是产品给的默认值，运维可在系统设置中查看、增删（删除内置词有二次警示）。黑名单之外的命令按**免确认词表**（白名单，分只读区与写区）与**执行模式**分派：词表只读区命令在智能/全自动档直接执行；词表写区与词表外命令智能档弹窗确认、全自动档直接执行、「每次确认」档一律弹窗。目标越权（命令指向对话所选设备范围之外等）的命令无论如何设置都强制人工确认。单台设备还可叠加设备级策略（更严的黑名单或更宽的免确认词表，见 [第 5 章](./05-devices.md)）。

在此之上还有一层**会话执行态**闸：AI 会话默认处于 plan 态（只读调查——只执行只读命令，变更操作以文本方案输出），经二次确认切到执行态后才执行变更命令。黑白名单与词表内容在系统设置中维护（见 [第 10 章 系统设置](./10-settings.md)）。

## 数据存放位置

灵枢的所有数据（设备台账、拓扑、凭证密文、知识库文档、日志）都存放在本机用户数据目录下的 SQLite 数据库文件中，不上传云端（AI 对话发往模型服务商的例外见上文「灵枢是什么」）。数据库自带定期备份（双桶轮换），升级迁移前还会再做一次安全备份。
