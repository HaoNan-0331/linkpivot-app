# 第 5 章 设备管理

## 功能概述

设备管理是设备台账的主要维护入口，侧边栏「设备管理」分组下有两个子入口：

- **设备列表（手工资产）**：新增/编辑/删除设备、为每台设备配置四类远程通道凭证（SSH / Telnet / Web 界面 / RDP 远程桌面）、并行测试全部通道连通性、复制设备、处理重名、维护设备级命令策略、查看设备配置变更历史。纳管进来的 Windows 主机也会出现在此列表中（见下文「Windows 主机（托管资产）」）。
- **Windows 主机（托管资产）**：安装了灵枢客户端、自动回连受管的 Windows 机器，含部署、在线状态、手动执行命令等专属管理面（见本章末节）。

设备是拓扑节点、AI 上下文、自动发现、采集任务等一切功能的数据基础。拓扑页右侧栏也能编辑设备、彻底删除设备，以及把画布上未登记的节点补录为设备（纳管，即把只存在于拓扑图、尚未进入台账的节点收编进设备台账），使用的表单与本页相同（见 [第 4 章 拓扑管理](./04-topology.md)）。

## 界面布局

页面顶部标题条左侧显示页面标题「设备管理」与副题「手工资产与连接通道」。其下工具条左侧为设备计数「共 N 台设备」，右侧是「添加设备」主按钮。再往下依次为：重名提示条（仅存在存量重名时出现）与设备表格。表格从左到右列依次为：设备名称、类型、厂商、型号、IP、连接方式、操作（操作列从左到右六个图标按钮：测试连接、编辑、复制、命令策略、配置变更历史、删除）。表格不分页，当前版本也不提供搜索与筛选，直接列出全部设备（设备较多时需全量滚动查找）。

Windows 主机行的差异：类型为「Windows 主机」；不显示「复制」按钮（托管主机不能手工复制新建）；「删除」确认文案为「删除将吊销该主机的回连凭证，并向在线主机下发客户端自卸载指令。确定删除？」。

### 设备表单（添加 / 编辑 / 复制共用）

表单弹窗标题按模式显示「添加设备」「编辑设备」或「复制设备」（宽约 600 像素）。上半部为基本信息，下半部为四个通道页签。

#### 四通道页签

页签从左到右固定为：SSH、Telnet、Web 界面、RDP 远程桌面。每个页签标题在通道已启用时带一个绿色小圆点（表示「已配置」）。

Windows 主机编辑态额外有第五个页签「command_executor」（回连通道，排最后）：纯状态呈现、无任何凭证字段——说明文字「该通道由客户端纳管自动配置，回连凭证由服务端托管，无需填写」、绑定识别码（按设备经主机列表解析，解析不到显示「—」）与「已托管」徽标；已绑定时页签同样亮绿色圆点。手工资产表单永远只有四个页签；保存时回连通道节被结构性过滤，表单绝不会误删该通道。

**每个通道页签顶部是一个启用开关（Switch）**，语义：

- 开关是通道启用/禁用的唯一权威：开着才启用该通道凭证；
- **填了即启用**：在任意凭证字段输入内容，开关自动打开（防止填了凭证却没启用的隐性错误）；
- 清空字段不会自动关闭开关（禁用必须显式拨 off，防误触丢配置）；
- 拨 off 后该通道字段全部置灰（值保留在界面，可拨回反悔）；
- **编辑模式下把原本已配置的通道拨 off**，开关旁出现琥珀色警示「保存后将删除该通道已存凭证」；保存后该通道凭证即被删除。

**SSH 页签字段：**

| 字段 | 说明 |
| --- | --- |
| 端口 | 数字输入，1~65535，占位「22」 |
| 账号 | 登录用户名 |
| 密码 | 密码框。已存密码时占位提示「已存 ****尾4，留空则不修改」（尾4 为已存密码末四位）；编辑未改密时占位「留空则不修改」；留空提交 = 保持原密码不变 |
| SSH Key 文件路径 | 占位「C:/Users/.ssh/id_rsa（可选）」；与密钥内容二选一即可 |
| 或粘贴 SSH Key 内容 | 多行文本。已存密钥时占位「已存密钥（****尾4），留空则不修改；粘贴新内容将覆盖」；新建设备占位示例私钥开头 |

SSH 支持密钥与密码两种认证；同时填写时以密钥优先。

**Telnet 页签字段：** 端口（占位「23」）、账号、密码（占位规则同 SSH）。Telnet 为明文协议，仅用于只支持 Telnet 的旧设备。

**Web 界面页签字段：** Web URL（占位「https://192.168.1.1」）。连接时用系统浏览器打开该地址。

**RDP 远程桌面页签字段：**

| 字段 | 说明 |
| --- | --- |
| 端口 | 占位「3389」 |
| 账号 | 远程桌面用户名 |
| 密码 | 预留字段：加密存储但连接时由系统远程桌面客户端自行提示输入密码（.rdp 文件格式限制，不支持明文密码行）；其余占位规则同 SSH |
| 分辨率 | 占位「1920x1080（可选）」，格式为「宽x高」（字母 x）；留空 = 不指定；格式不符时连接将忽略该值使用默认分辨率 |

#### 凭证「留空=不修改」规则（编辑模式）

编辑已配通道时，密码与密钥内容**永不回填明文**（界面只见过占位提示「已存 ****尾4」），留空提交即保持已存凭证不变；端口、账号、密钥路径、Web URL、分辨率这些非敏感字段会回填当前值，提交时按表单现值写入——把这些字段清空后保存即真实清除该字段。

#### 默认通道选择与滑落

- 默认通道下拉选项永远只包含当前开关开启的通道；
- 现选默认通道被关闭后，表单内自动滑落到固定顺序（SSH > Telnet > Web > RDP）中下一个开启的通道，无提示；
- 全部通道关闭后默认通道置空（显示「未配置」），可保存为零通道设备；
- 不手动选择时，保存由服务端按同样规则收敛（首条已开启通道）。

### 重名提示条与重名设备清单

历史数据若存在同名设备（旧版本未启用唯一约束时产生），设备页顶部出现黄色提示条：「存在 N 组重名设备（共 M 台），处理后自动启用名称唯一防护」，右侧「查看清单」红色小按钮。

点开「重名设备清单」弹窗（宽约 720 像素）：按重名组折叠展示，组标题为「{设备名} ×{台数}」，展开后每台设备一行：IP / 型号 / 厂商区分信息 + 名称输入框（内联编辑）+「保存」按钮（输入为空或与原名相同时禁用）。单台改名即时保存，提示「已改名为『{新名}』」，改完该组即消失。

全部清零后弹窗显示绿色「唯一防护已启用 ✓」与说明「所有重名已处理，数据库唯一索引已自动建立，后续同名保存将被拦截。」提示条同步消失。

### 设备命令策略弹窗

操作列盾牌图标打开，标题「命令策略：{设备名}」。为单台设备定制命令裁决策略，**设备策略优先于全局策略**（说明行原文：「设备策略优先于全局策略；全局黑名单（内置与追加）任何设备不可放开。」；Windows 主机附注「（Windows 主机按 Windows 命令集裁决）」）。两区纵向排列：

- **设备黑名单（直接拒绝）**：输入框占位「输入命令首词，如 reload」（Windows 主机为「输入命令首词，如 format」）——命中即拒，比全局黑名单更严；
- **免确认区（直接执行）**：输入框占位「输入命令，如 show」（Windows 主机为「输入命令，如 tasklist」），说明「设备免确认词表优先于全局；名单外命令智能档需确认、全自动档直接执行」。

两区空态均显示「未设置（跟随全局策略）」；跨区查重（同一命令不能同时进两区，命中提示「该命令已存在」）；单「保存」提交，成功提示「命令策略已保存」，失败提示「命令策略保存失败：{原因}」且弹窗不关可重试。加载失败时停用编辑面并给出重试（防空集假象下保存清空既有策略）。

设备两级策略在整个命令裁决链中的位置（与 [第 7 章](./07-ai-assistant.md)「命令裁决链」同一条链，顺序固定不可调换）：结构校验（分隔符/危险字符/管道规则——管道规则含写动作硬拦：`| redirect`、`| tee`、`| append` 与行内裸 `>` / `>>` 重定向命中即拒，报「禁止的管道写动作: …」或「命令包含重定向写」，防 `show run` 这类查询结果被重定向外传，不随任何名单与档位放开）→ 全局黑名单硬底 → **设备黑名单** → 白名单区匹配（**设备词表遮蔽全局**——设备配了该词按设备分区裁决，没配才看全局）→ plan 态闸 → 执行模式三档分派（每次确认/智能/全自动）。通俗地说：设备黑名单只能在全局之上「多拒」；设备免确认区决定该设备的命令在智能档是否免确认；全局黑名单是任何设备级策略都放不开的底线。

### 配置变更历史弹窗

操作列历史图标打开，标题「配置变更历史：{设备名}」。展示这台设备上 AI/手动执行写命令留下的配置变更记录（写命令执行时自动抓取配置快照，见 [第 7 章](./07-ai-assistant.md) 核对结论行）。四列表格：时间（悬停完整时间戳）/ 命令（代码字体，悬停全文）/ 来源（标签二值：AI 或手动）/ 核对（四态，与执行卡核对结论行同色同文案：✓ 配置变更已核实 / ⚠ 快照不符：未见预期变更 / 此通道无快照 / ⚠ 后快照缺失，待下次写命令补比对）。每页 10 条分页；被拒绝的命令不进此表（未执行无变更，拒绝记录可到 [第 9 章](./09-log-audit.md) 日志审计页查）。

点击行首展开该条变更的**脱敏 diff 对照**：红色 = 变更前、绿色 = 变更后（配置中的密码行等敏感内容已掩码）；「已核实/快照不符」两态的行才加载 diff；「此通道无快照」「后快照缺失」两态的行不请求 diff，展开显示对应提示。Windows 主机同样留历史，核对列显示「此通道无快照」。重开弹窗回到第一页。

## 设备能力与下游功能的关系

设备配置的通道决定了它在其他模块中的可用能力（界面上不直接展示能力字段，但以下功能依赖它们）：

| 通道配置 | 拓扑双击 | 自动发现 | 采集任务 | AI 执行命令 | AI 设备上下文档位 |
| --- | --- | --- | --- | --- | --- |
| SSH | 可连 | 可参与 | 可作为采集源 | 可执行命令 | 可执行 |
| Telnet | 可连 | 可参与 | 可作为采集源 | 可执行命令 | 可执行 |
| Web 界面 | 可连（浏览器打开） | 不参与 | 不参与 | 不执行 | 仅问答（可检索知识/经验，不能执行命令） |
| RDP 远程桌面 | 可连（远程桌面窗口） | 不参与 | 不参与 | 不执行 | 仅问答 |
| 绑定了 MCP 工具 | — | — | — | 经 MCP 工具操控 | 可调 MCP |
| Windows 主机（托管） | — | — | — | 经回连通道执行（按 Windows 词表裁决） | 可执行 |

设备能力四要素（有无 SSH、有无 Telnet、有无 MCP 绑定、有无托管命令通道）由后台根据通道配置自动派生，AI 助手选择设备上下文时按此标注档位（详见 [第 7 章](./07-ai-assistant.md)「设备上下文选择器」）；有 SSH、Telnet 或托管命令通道任一，该设备即可作为 AI 执行目标。

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 命名全局唯一 | 设备名经归一化（忽略大小写与首尾空白等）后全局唯一：失焦预检 + 保存时服务层事务内硬拦截（双重防线）；冲突错误含对方设备名与 IP |
| 单份复制 | 复制只继承非凭证字段（名称/类型/厂商/型号/版本/IP 可改）；四通道凭证全部需要重新输入——源凭证永不出现在界面 |
| 凭证加密 | 所有密码/密钥内容 AES-256-GCM 加密落库；界面回显永远只有「****尾4」脱敏形态 |
| 通道数上限 | 一台设备最多四通道各一份（每通道一条凭证记录）；Windows 主机另有系统托管的回连通道（command_executor），不经表单、不可手工增删 |
| 端口范围 | 1 ~ 65535 |
| 删除级联 | 删除设备同时从所有拓扑移除其节点，事务化 |
| 保存事务化 | 设备增删改均为单事务：失败整体回滚，界面不落半截数据 |
| 升级自动迁移 | 从旧版本（单通道凭证平铺）升级到当前版本时，历史凭证自动迁移到按通道存储，无需人工处理 |
| IP 格式 | 严格 IPv4：四段 0-255 纯十进制、禁前导零、不得带空格等多余字符；非法格式表单红字拦截，无法保存 |
| IP 重复 | 警告级（黄色）允许保存；复制模式同源 IP 硬拦 |
| RDP 分辨率 | 「宽x高」格式才生效（如 1920x1080），否则忽略 |

## 典型操作流程：添加并验证一台新设备

1. 点右上角「添加设备」。预期弹出「添加设备」表单。
2. 填写设备名称（如「核心交换机-01」）、类型、厂商、IP（如 192.0.2.10）。预期名称失焦无红色查重提示，IP 无黄色警告。
3. 打开 SSH 页签开关（或直接在端口/账号字段输入，开关自动打开），填端口（默认占位 22）、账号、密码（或密钥）。预期页签标题出现绿色小圆点。
4. 「默认通道」下拉此时应已包含 SSH（表单自动滑落选中）；如需 Telnet 为主可再开 Telnet 页签并改选默认通道。
5. 点「确 定」。预期提示「设备添加成功」，表格出现新行，「连接方式」列显示「SSH」。
6. 点该行「测试连接」图标。预期绿色提示「核心交换机-01: SSH 连接成功 (192.0.2.10:22)」（多通道时为顶部通知卡逐通道 ✓/✗）。
7. 到 [第 4 章 拓扑管理](./04-topology.md) 用画布右下角「+」把该设备加入拓扑，或直接双击拓扑节点验证连接。

## Windows 主机（托管资产）

侧边栏「设备管理 → Windows 主机」进入。与手工资产（设备列表）相对：这里的机器通过**安装灵枢客户端**自动回连受管——你分发安装包，Windows 机器安装并运行客户端后自动出现在主机列表，无需手工添加台账、无需在每台机器上配凭证（回连凭证由系统自动签发管理）。

### 界面布局

标题「Windows 主机」，右上「刷新」文字按钮与「下载客户端」主按钮。其下依次为：部署码工具条 → 主机列表（或空态）→ 待纳管面板 → 黑名单面板（后两者默认折叠）。

### 部署码与下载客户端

- **部署码工具条**：左侧「部署码」标签 + 状态徽标（三态：「有效 · 剩 N 天」/「已过期」/「已吊销」）——工具条不显示码值本身（码值只烙印在生成的安装包内）。「吊销并重置」红色按钮弹出确认「吊销并重置部署码？」（正文说明：吊销后所有已分发的安装包立即失效，无法再用于纳管新主机；已纳管主机不受影响，凭长效凭证继续回连；吊销同时生成新的部署码，下次下载使用新码），用于部署码疑似泄露时的一键止损。
- **「下载客户端」**：弹窗「下载客户端安装包」——选择服务地址（默认自动选取本机首个可用 IP，可改；客户端回连该地址）后点「生成安装包」，生成内嵌部署码与服务地址的客户端安装包（成功提示「安装包已保存：{路径}」），分发给目标 Windows 机器即可。安装包烙印所需的回连加密证书由灵枢自动生成并保管，证书生成组件随灵枢安装包内置（无需本机预装 Git/openssl 等任何外部工具，纯净 Windows 机器开箱可用，组件每次使用前自动校验完整性）；若杀毒软件误报隔离了灵枢安装目录内的组件导致证书不可用，生成安装包会报「安装包生成失败：主机接入证书指纹不可用（证书未生成或异常），请重启灵枢后重试」——将灵枢安装目录加入杀毒软件白名单或重装灵枢后重试。

空态（暂无主机时）显示「暂无已纳管主机 / 点击「下载客户端」生成安装包，分发给 Windows 机器。安装完成后主机自动出现在此处，无需手工添加。」

### 主机列表

七列：友好名 / 识别码（客户端唯一标识，代码字体）/ IP 地址 / 系统版本 / 状态 / 最近执行 / 操作。

- **状态列**：在线主机显示「● 在线」（有上线时长时如「● 在线 · 2 小时」，时长四档：刚上线/N 分钟/N 小时 M 分/N 天 M 小时，悬停显示「上线于 {完整时间戳}」）；离线显示「● 离线 · {时间}」（时间四档：60 分钟内为「N 分钟前」、今天为「HH:mm」、今年为「MM-DD HH:mm」、跨年为「YYYY-MM-DD」，悬停完整时间戳）；长期离线显示琥珀色标签「长期离线 · {时间}」；从未在线只显示状态词。长期离线主机整行文字置灰（编辑/删除仍可用）。每行可展开三行只读信息：原始主机名 / 首次纳管（完整时间戳）/ 备注全文。
- **最近执行列**：最近一次手动执行命令的微标（相对时间 · 成功/失败，结果着色）；已执行过时整格可点击，跳转 [第 9 章](./09-log-audit.md) 日志审计页并按该主机预筛；从未执行显示「—」。
- **操作列**：编辑（弹窗改友好名称与备注——友好名称必填，默认取主机名，可改为易识别名称；备注可选 500 字）/ 执行命令（在线主机专属，见下）/ 删除（确认文案按在线态二选一：在线为「删除将吊销该主机的回连凭证，并向在线主机下发客户端自卸载指令。确定删除？」，离线为「删除将吊销该主机的回连凭证，离线主机收不到卸载指令，但将永远无法回连。确定删除？」）。

### 执行命令弹窗

操作列「执行命令」打开（离线主机按钮禁用，悬停提示「主机离线，无法执行命令」）。三段式：

1. **输入**：目标主机行（友好名 + 识别码）+ 四类快选下拉（网络诊断：ping、tracert、nslookup 等；系统信息：systeminfo、hostname 等；进程服务用户：tasklist、Get-Service、quser 等；磁盘卷：Get-Volume 等，可搜索）+ 单行命令输入框——选快选即回填命令，也可直接输入；
2. **执行中**：转圈 + 已耗时秒数，可「取消」（取消只是放弃查看，命令在主机上照常执行完毕并留审计）；
3. **终态**（三选一）：正常返回——退出代码（0 绿/非 0 红）+ 耗时秒数 + 命令输出滚动区（标准/错误输出分区，「复制」按钮可复制全文，无输出显示「（无输出）」）；执行超时——红标「执行超时」，说明「命令超过 60 秒未返回，已放弃等待。可精简命令后重试。」；连接中断——红标「连接中断」，说明「主机在执行期间断开，未收到结果。主机恢复在线后可重试。」重跑整体替换旧结果不堆叠。

命令下发前经与 AI 执行同一条裁决链校验（Windows 通道）：黑名单命中直接拒绝；结构防线拒绝含危险字符（> < $ { } % ( )）、分隔符注入、超过 2 段的管道，且管道第二段首词必须命中 [第 10 章](./10-settings.md) 的管道过滤集；免确认词表命中的命令直接执行，词表外的单段命令同样放行（你手敲发起的主权命令，词表是免确认分级依据而非硬边界）。命令下发失败（主机不在线/被防线拦截等）直接提示原因，弹窗停留输入态可改可重试。每次执行（含取消查看的）都记入 [第 9 章](./09-log-audit.md) 日志审计，来源标注「手动执行」；执行成功的写命令同样进配置变更历史（核对列「此通道无快照」）。

### 待纳管与黑名单

- **待纳管面板**（默认折叠，有新主机时红点徽标提示）：只有**异常回连**会进此列表——使用有效部署码回连的主机被自动纳管、直接进主机列表；无码或码失效的陌生客户端回连才落入待纳管（此时应用内弹顶部通知「发现未知识别码回连」，点击自动跳到本页并展开待纳管面板）。列表六列：识别码 / 主机名 / IP 地址 / 系统版本 / 首次回连时间 / 操作。两个动作——「纳管」弹出设备表单的纳管形态（标题「纳管主机」、确认键「确认纳管」；预填主机名→设备名称、IP、系统版本→版本，类型锁定 Windows 主机、厂商免必填，可顺手补配 RDP 等通道；确认后入台账并转入主机列表，提示「纳管成功」，资料保存失败时提示「纳管成功，但信息保存失败：{原因}」）/「拒绝」（确认文案「拒绝后该识别码将加入黑名单，不再出现在待纳管列表。可在黑名单中解除。」确认后删除待纳管记录并拉黑该机器）。
- **黑名单面板**（默认折叠，灰徽标）：被拒绝过的机器记录（识别码/主机名/拉黑时间）。「解除」经确认（「解除后，该机器下次回连将重新进入待纳管列表。」）后，该机器下次回连将重新进入待纳管列表。

### 与 AI 助手的联动

纳管后的 Windows 主机出现在 AI 助手的设备选择器中，可作为 AI 执行目标；AI 对其执行的命令按 Windows 词表（全局 + 设备级策略）裁决，写命令同样进入配置变更历史与核对链（见 [第 7 章](./07-ai-assistant.md)）。

## 常见问题

**Q1：编辑设备时密码栏是空的，保存会不会把密码清掉？**
不会。密码/密钥内容留空 = 不修改已存凭证；占位提示「已存 ****尾4，留空则不修改」就是为了表明这一点。想换密码时输入新值提交即覆盖。

**Q2：一台设备能同时配 SSH 和 Telnet 吗？**
能。四通道相互独立，可同时启用任意多类；「连接方式」列会显示如「SSH +1」，悬停可看全清单。

**Q3：测试连接测的是什么？**
对已配置的每个通道做连通性探测：SSH 实际尝试登录验证凭证；Telnet 与 Web/RDP 同为端口可达性探测，不验证账号密码。多通道时并行探测、结果逐通道展示。

**Q4：复制设备后为什么还要填一遍密码？**
安全设计：凭证只在后台加密存储，复制时不透传到界面（防止凭证在界面层流转）；新设备凭证视为全新输入。

**Q5：设备名提示「名称已存在」但列表里没看到同名设备？**
唯一性按归一化名称判定（忽略大小写与空白差异），可能与其他设备名仅在大小写上有别；错误信息会给出冲突设备名与 IP，去改其中一个即可。

**Q6：拨通道开关旁出现橙色字「保存后将删除该通道已存凭证」？**
这是在编辑模式下关闭一个原本已配置的通道的明确警示。确认不需要该通道了再保存；拨回开关即可反悔。

**Q7：删设备会把拓扑弄坏吗？**
不会。删除是事务化级联：设备与其在所有拓扑中的节点一并移除；失败则整体回滚，两边都保持原状。

**Q8：SSH 密钥认证和密码认证填哪个？**
按设备实际支持的认证方式填其一即可；两者都填时密钥优先。密钥可用「文件路径」指向本机私钥文件，或直接「粘贴密钥内容」（完整含 BEGIN/END 行）。SSH 私钥是成对密钥认证中保存在本机的那一半，相当于免输密码的登录凭证——对应的公钥需预先部署在设备上。

**Q9：RDP 分辨率写了没生效？**
检查格式：必须是「宽x高」形如 1920x1080（中间是字母 x）。格式不符时连接会忽略该值，使用客户端默认分辨率。

**Q10：「连接方式」列显示「—」是什么意思？**
该设备未配置任何登录通道。零通道设备可以保存（作为纯台账记录），但无法双击连接、不参与自动发现与采集任务。

**Q11：IP 填了 192.0.2.01 或 300.1.1.1，提示「IP 格式无效：需纯 IPv4 四段 0-255（禁前导零）」？**
IP 输入与保存前按严格 IPv4 校验：每段必须是 0-255 的纯十进制数、不能有前导零（01 不行，1 可以）、不能带空格或多余字符。去掉前导零、把超界段改到 0-255 区间即可通过。

**Q12：设备级「命令策略」和设置页的全局黑白名单谁说了算？**
设备策略优先于全局策略：设备黑名单比全局更严（可以拒掉全局放行的命令），设备免确认词表优先于全局词表（该设备上的词按设备分区裁决）；但全局黑名单（含内置词）任何设备都放不开——这是底线。完整裁决顺序见上文「设备命令策略弹窗」。

**Q13：配置变更历史里有些行没有 diff 可展开？**
该条记录的核对态为「此通道无快照」或「后快照缺失」时没有快照对照可看，展开显示对应提示；「已核实/快照不符」的行才加载脱敏 diff。

**Q14：Windows 机器怎么加入灵枢管理？**
到「设备管理 → Windows 主机」页点「下载客户端」，生成安装包分发给 Windows 机器安装。安装包内烙印有效部署码的机器回连后**自动纳管**、直接出现在主机列表（无需人工确认）；只有无码或码失效的异常回连才进「待纳管」列表，点「纳管」补充资料后正式入台账——全程无需在 Windows 机器上手工配凭证。

**Q15：部署码「吊销并重置」会影响已纳管的主机吗？**
不会。吊销只让**尚未安装的**安装包失效（防泄露）；已纳管主机的回连凭证独立签发，不受影响。吊销同时会生成新的部署码，下次下载的安装包使用新码。

**Q16：Windows 主机上手动执行命令有词表限制吗？**
有硬防线：手动执行与 AI 执行同经一条裁决链——黑名单命令一律拒绝，Windows 通道另有危险字符与管道规则（管道第二段须命中管道过滤集）。免确认词表命中的命令直接执行；词表外的单段命令在手动执行中同样放行（手敲主权），但每次执行都入日志审计（来源「手动执行」）。

**Q17：生成客户端安装包需要预装 Git 或 openssl 吗？**
不需要。证书生成组件随灵枢安装包内置分发，每次使用前自动做完整性校验，无 Git 的机器同样开箱可用。若生成时报「安装包生成失败：主机接入证书指纹不可用（证书未生成或异常），请重启灵枢后重试」，多为杀毒软件误删/隔离了安装目录内组件——恢复文件并将灵枢加入白名单，或重装灵枢后重试。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 通道凭证 | 某一类远程通道（SSH/Telnet/Web/RDP）的登录信息（端口/账号/密码/密钥/URL 等） |
| 启用开关 | 每个通道页签顶部的 Switch，通道启用状态的唯一权威 |
| 填了即启用 | 在凭证字段输入内容会自动打开该通道开关的联动规则 |
| 留空不修改 | 编辑时密码/密钥留空提交表示保持已存值不变的语义 |
| 默认通道 | 双击直连与 AI 执行命令优先使用的通道，可手动选择或自动滑落 |
| 滑落 | 默认通道失效时自动降级到固定顺序下一可用通道的规则 |
| 已配圆点 | 通道页签标题上的绿色小点，表示该通道已启用 |
