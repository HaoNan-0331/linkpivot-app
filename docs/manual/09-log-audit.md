# 第 9 章 日志审计

## 功能概述

日志审计集中查询三类留痕：**AI 助手执行日志**（AI 在设备上执行命令的每条记录，含越权拦截审计，以及命令输出、耗时、退出码等执行结果面）、**AI 系统执行日志**（拓扑发现等系统级 AI 调用，以及升级更新、周期备份、数据迁移、安全告警等系统运行事件的留痕）与 **LLM 报文**（每次 AI 调用发送给大模型的完整请求与返回的原始响应原文，一字不差留痕，用于排障取证）。用于事后追溯「AI 干了什么、依据什么、结果如何」，安全审计（越权命令的处理结果），以及按追踪号报障取证。

升级、备份等系统运行事件与拓扑发现日志写入同一张系统日志表，都在「AI 系统执行日志」页签中一并展示；本章是 AI 执行日志与 LLM 报文在当前版本的唯一查询入口。

## 界面布局

页面顶部一行页签：「AI 助手执行日志 | AI 系统执行日志 | LLM 报文」（默认第一项）。每个页签为一张卡片：标题栏右侧「刷新」按钮，卡内一行筛选工具栏 + 结果表格。筛选**即选即查**——任一筛选变化立即重新查询并回到第 1 页，没有「查询」按钮。三个页签的表格均为**服务端分页**：默认每页 50 条，可在 20/50/100/200 四档间切换，支持直接跳页并显示总条数；筛选收窄或页大小放大后当前页越出末页时，自动跳回末有效页。加载失败会弹出错误提示（不再静默）。

### AI 系统执行日志页签

记录拓扑自动发现等系统级 AI 调用，也收录升级更新、周期备份、数据迁移、安全告警等系统运行事件（卡片标题仍为「AI 系统执行日志（拓扑发现）」，为历史命名）。系统事件行一般没有设备与 Prompt/AI 响应（详情弹窗中显示「(空)」），信息集中在消息列。

筛选工具栏三维（无设备与来源维）：时间五档分段器（同执行日志页签）+ 状态下拉（两组：成功 / 失败，警告归入失败组）+ 关键词框（占位「搜索消息」，检索消息列，回车或清空触发）。

表格列：时间 / 状态（成功绿；失败与警告统一红色「失败」）/ 设备（参与设备名列表，超长省略）/ 消息（超长省略）/ 操作（「详情」）。**消息列**按行分色：成功行的消息为正常文本色（成功行也会写结果摘要，如采集条数），失败与警告行红字告警。分页与服务端筛选行为同执行日志页签。

**系统日志详情弹窗**：标题「系统日志详情 — 成功/失败」；内容为设备、**追踪号**（同执行日志详情形态）、消息/错误（成功行前缀「消息」正常色，失败与警告行前缀「错误」红字——有值即显示，不判断状态）、发送给 AI 的 Prompt、AI 原始响应、解析结果（绿色区块，有值即显示——同样不判断状态）。

### LLM 报文页签（wire 记录）

**这是什么**：每次 AI 调用（不限于对话——含 Agent 循环、拓扑发现、经验起草、知识库检索、报告生成、提示词优化等全部调用域）发送给大模型的完整请求报文与返回的原始响应报文，一字不差原样加密落库，含 system prompt 与全部历史消息。排障时用于查看「网关实际收到 / 返回的现场」：提示词没生效、上下文丢失、模型返回异常等疑问都能在此对账。默认开启；报文明细保留 30 天（超期自动清理）；可在 系统设置 → 通用设置 →「LLM 报文记录」开关卡关闭（关闭后新调用不再记录，已有记录不受影响，见 [第 10 章](./10-settings.md)）。

**脱敏与截断规则**：报文中的图片以摘要占位符替代（不重复存储图片数据）；单侧报文超过 512KB 时保头截断，详情中显示金色「已截断」标签（悬停说明尾部 hash 可用于完整性对照）；截断后的存储态原文可整体复制（巨型报文的完整性逃生通道）。

**筛选工具栏**：时间五档分段器（同前）+ 调用域下拉（八域：对话 / Agent 循环 / 拓扑发现 / 经验起草 / 重排序 / 知识库 / 报告生成 / 提示词优化）+ 状态下拉（成功 / 失败）+ 关键词框（占位「搜索追踪号 / 模型名」，可粘追踪短码或模型名直查，回车或清空触发）。

**表格列**：时间 / 追踪号（8 位短码，可复制）/ 调用域 / 模型 / 状态 / 尝试（#N）/ 耗时 / 报文大小（请求+响应合计）/ 操作（「详情」）。同一次调用发生重试时，每次尝试各占一行——追踪号相同、「尝试」列标 #1/#2/…；无法归属到具体会话回合的调用（如后台独立调用）调用域显示「未归属」。

**空态三分流**：仅关键词有值且查无 →「未找到追踪号对应的报文」（附提示：报文明细保留 30 天，超期或关闭期间调用的报文不可查）；其他筛选命中 0 →「所选筛选条件下暂无匹配报文」；无任何筛选且无记录 →「暂无 LLM 报文记录」（附默认开启与保留期说明）。

**报文详情弹窗**（宽约 720 像素）：顶部元数据摘要两行——「调用域 · 模型 · 状态」与「耗时 · 报文大小 · 追踪号（可复制）」；有截断或多次尝试时附加「已截断」标签与「尝试 N 次」。主体按尝试分块：仅一次尝试时直接展示；多次尝试时每次尝试一折叠块（「第 N 次尝试 · 成功/失败 · 耗时」），其中每次尝试内为「请求报文」「响应报文」两个折叠面板（默认收起，首次展开才渲染）。展开后的报文渲染为**可折叠的 JSON 树**：messages 逐条成节点、工具调用（tool_calls）嵌套展示、超长字符串截断、超大节点折叠为摘要行。两个折叠标题右侧各有复制按钮，可复制该侧存储态原文。降级提示各有对应文案：解密失败显示安全警告；工具定义超保留期显示「工具定义已随保留期清理，无法还原 tools 字段」；无响应体显示「无响应体（连接层失败——请求未到达网关或连接中断）」。

## 典型排查流程：追查一次可疑的 AI 命令

1. 切到「AI 助手执行日志」页签。预期表格显示最近的执行记录；需要缩小范围时用工具栏筛选——时间档圈定时间段、状态下拉选「拦截拒绝」、设备下拉锁定设备，或在关键词框粘贴命令片段。
2. 切换视图到「越权记录」。预期列表只剩命中越权规则的记录；空列表说明近期无越权命中。
3. 需要锁定特定结果时，用二级筛选选「用户确认放行」「用户取消」或「中断（崩溃/断电）」。
4. 找到目标记录，点行尾「详情」。预期弹窗展示：设备名、完整命令、状态、追踪号、模式，Prompt 区（或「本轮共享上下文」展开全文）与「AI 原始响应」两个区块，以及末尾的「LLM 报文（调用现场还原）」折叠区（如有）。
5. 核对三点：命令是否合理、AI 原因是否与命令一致、当时用户侧的处理（放行/取消/中断）是否符合预期。命中规则列（越权视图）悬停可看规则解释；需要网关级一字不差现场时，展开「LLM 报文」对看该次调用的完整请求与响应。
6. 拿着详情里的追踪号，也可直接在关键词框粘贴短码检索关联记录，或到「LLM 报文」页签按短码直查该次调用的完整报文。

## 执行日志字段说明

| 字段 | 含义 |
| --- | --- |
| 时间 | 记录生成时间（本机时区） |
| 设备 | 命令执行的目标设备名 |
| 命令 | 实际在设备上执行的命令原文（超长省略，详情可见全文；沙箱记录为所执行的代码全文，截断至 10000 字符） |
| 状态 | 已批准 / 已拒绝 / 待确认 / 已执行 / 执行失败 / 中断（崩溃/断电） |
| 追踪号 | 记录的 8 位报障短码，详情弹窗中可一键复制，按号可定位全链路日志 |
| 来源 | 触发来源七值：对话 / Agent 循环 / 拓扑发现 / MCP 工具 / 只读检索 / 手动执行（Windows 主机页发起）/ 沙箱（sandbox，AI 代码执行，来源列显示原文） |
| 拒绝原因 | 命令被拒的具体原因（黑名单命中、词表外拒绝、单轮工具调用超上限等） |
| 模式 | 触发时的执行模式：确认（confirm）/ 智能（smart）/ 自动（auto）/ 手动（manual） |
| AI 原因 | AI 提议执行该命令的理由摘要（子代理巡检命令固定为「子代理只读巡检」） |
| 处理结果（越权视图） | 用户确认放行 / 用户取消 / 中断（崩溃/断电） |
| 命中规则（越权视图） | 越权判定命中的规则编号，悬停看解释 |
| Prompt / AI 响应 | 详情弹窗内的完整上下文与 AI 原始回复；Agent 批量命令记录为「本轮共享上下文」（展开可看该轮原始交互全文） |
| 执行结果面 | 命令输出、耗时、退出码、错误码、是否超时等，随记录加密落库（数据层留痕，供追溯与自进化分析） |
| LLM 报文 | 该命令关联 AI 调用的请求/响应原文，详情弹窗末尾折叠区与「LLM 报文」页签可查 |

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 记录范围 | AI 每次在设备上执行命令都会留痕（无论成功失败），命令输出、耗时、退出码等执行结果面一并加密落库；AI 检索本地知识库、经验库、装载技能时也会各留一条审计记录（来源「只读检索」，命令列形如「kb:query 关键词」「exp:query 关键词」「skill:load 技能名」，设备列为空）；Windows 主机页「执行命令」弹窗的手动执行记为来源「手动执行」；Agent 循环来源涵盖 AI 自主任务全链——含任务目标（goal）驱动轮与子代理批量巡检命令（子代理命令的 AI 原因为「子代理只读巡检」，审计落盘失败时该命令拒绝执行）；AI 沙箱代码执行以独立来源 sandbox 留痕（设备列为空）；拓扑发现的 AI 调用与升级、备份、迁移、安全告警等系统事件入系统日志；每次 AI 调用的请求/响应原文入 LLM 报文（全调用域覆盖，失败请求也全记） |
| 筛选与分页 | 三个页签均支持时间筛选与服务端分页（默认每页 50 条，20/50/100/200 四档可调，支持跳页与总条数显示）；筛选即选即查，任一变化自动回到第 1 页；当前页越出末页自动跳回末有效页 |
| 保留策略 | 执行日志与系统日志当前无自动清理，会随使用持续累积；LLM 报文明细保留 30 天、超期自动清理（默认开启，可在设置页通用设置关闭）；设置页的「保留天数」不作用于本章执行/系统日志（见 [第 10 章 系统设置](./10-settings.md)）。Prompt、AI 响应与 LLM 报文均加密存储 |
| 越权终态语义 | 唯一放行路径是当时点了「确认执行」；用户在场的未决（点取消、关弹窗、切界面、确认超时）统一记「用户取消」；崩溃、断电、退出应用等进程中断的未决在下次启动或刷新日志时由后台对账订正为「中断（崩溃/断电）」 |
| 短码检索 | 执行日志页签关键词框除命令/拒绝原因外，支持粘贴 8 位追踪短码定位对应审计行（及同回合关联行）；「LLM 报文」页签关键词框按追踪号/模型名直查 |
| 敏感内容 | Prompt/AI 响应与 LLM 报文原文仅在本页详情弹窗中展示，用于审计（本页是唯一查询入口）；LLM 报文本地加密存储，图片以摘要占位符替代，超 512KB 保头截断 |
| 时间显示 | 按本机时区格式化 |

## 常见问题

**Q1：模式列的「自动拦截」是什么意思？**
表示该记录产生时执行模式为全自动（auto），但命令命中越权规则被强制打断转为人工确认——全自动不代表越权免检。

**Q2：我没点过取消，为什么处理结果是「用户取消」或「中断（崩溃/断电）」？**
在场的未决收尾（点取消、关闭弹窗、切换页面、确认超时）统一归为用户取消；退出应用、崩溃、断电等进程中断则由后台对账订正为中断。这是审计口径，保证「放行必有显式动作」。

**Q3：怎么看 AI 当时为什么执行这条命令？**
点「详情」，「发送给 AI 的 Prompt」（或批量命令记录的「本轮共享上下文」展开全文）是当时的上下文与指令，「AI 原始响应」包含 AI 的原话与理由（AI 原因列是其摘要）。

**Q4：日志会占满磁盘吗？**
执行日志与系统日志不会自动清理，会随使用持续累积（系统日志各文本字段单条有截断上限，约 16000 字符，日常增长缓慢）；LLM 报文自动保留 30 天，超期自动清理，不会无限增长。长期高频使用的环境请留意数据库体积，需要清理时联系维护者按数据库方式处理。

**Q5：为什么有些记录的状态是「执行失败」？**
命令已获批准并执行，但在设备上执行出错（如设备返回错误、超时），详情中的 AI 原始响应可看到设备输出。

**Q6：日志能往前翻多早？**
三个页签均为服务端分页（每页默认 50 条，可调 20/50/100/200 并支持跳页），翻页可浏览库中全部历史——执行/系统日志无自动清理；LLM 报文保留 30 天，更早的已自动清理。需要长期归档或批量导出时，联系维护者按数据库方式处理。

**Q7：「待确认」状态的记录一直不变？**
待确认是短暂中间态（等待用户在 AI 对话中处理确认面板）；用户处理后状态更新为已批准/已拒绝。确认面板超过审批超时时间（默认 10 分钟）未处理会自动超时收尾，相关记录记为已拒绝；崩溃、断电、退出应用遗留的待确认行（含越权命中的行）会在下次启动或刷新日志时由后台对账订正为「中断（崩溃/断电）」，不会长期停留在待确认。

**Q8：详情里的「本轮共享上下文」是什么？和「发送给 AI 的 Prompt」有什么区别？**
Agent 批量执行命令时，同一回合的多条命令共享同一份 AI 上下文，日志按引用形态存储以避免重复。「本轮共享上下文（turn N · 事件 #a-#b）」点「展开查看本轮原始交互全文」即可回看该轮的原始交互记录（用户/AI 消息与工具执行结果）；「引用锚（溯源保留）」区块保留原始引用串供溯源。单条命令的记录仍是「发送给 AI 的 Prompt」直存形态。

**Q9：失败提示后面的「（追踪 xxxxxxxx）」是什么？**
8 位报障追踪短码，与日志详情里的「追踪号」同源。报障时提供此号即可按号定位全链路；也可自行在执行日志页签的关键词框、或「LLM 报文」页签的搜索框粘贴短码直查。

**Q10：LLM 报文页签里查不到某次调用？**
三种可能：该调用发生在升级到本版本之前（旧数据无 wire 留痕）；调用发生在「LLM 报文记录」开关被关闭期间；报文已超过 30 天保留期被自动清理。

## 与设置页日志查看器的关系

日志审计页是 AI 执行日志与 LLM 报文的唯一查询入口（当前版本系统设置页未挂载独立的日志查看器）。设置页通用设置的「LLM 报文记录」开关卡只控制是否记录（默认开，保留 30 天），查看仍在本页。本章页签已覆盖调试与审计两类场景：追提示词问题看详情弹窗的 Prompt/AI 响应原文与「LLM 报文」现场，追安全问题用「越权记录」视图，报障用追踪号。

| 保留策略 | 按天数自动清理超期数据的机制；执行/系统日志不适用，LLM 报文固定保留 30 天（ARP 历史与 AI 用量明细才有保留期设置） |

| 解析结果 | 系统日志详情中 AI 响应被解析后的结构化输出展示 |
