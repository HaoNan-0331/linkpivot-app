# 第 2 章 安装与登录

本章带你从零开始：安装灵枢 → 首次启动初始化管理员并保存恢复码 → 日常登录 → 忘记密码时用恢复码自助重置。每一步都写明「预期看到什么」。

## 安装

**第 1 步：获取安装包。**
从官方发布页（GitHub Releases）下载 Windows 安装包，文件名形如 `Setup.1.1.0.exe`（其中 1.1.0 为版本号，随发布更新）。

**第 2 步：运行安装包。**
双击 Setup.exe，按 NSIS 安装向导（Windows 上常见的标准安装程序界面）逐步完成安装；安装位置可自选（不改动则装到默认位置）。安装过程无需额外依赖，不需要预先安装 Node.js 或数据库。

**第 3 步：启动灵枢。**
从开始菜单或桌面快捷方式启动。预期看到：一个居中的加载转圈，随后进入以下两者之一：

- 全新安装（本地无账号数据）→ 进入「初始化管理员账号」界面（见下节）。
- 已初始化过 → 进入「登录」界面。

## 首次启动：初始化管理员并保存恢复码

首次启动时数据库中没有账号，灵枢会显示「初始化管理员账号」界面（左右双栏：左侧为灵枢产品信息面板，右侧为表单面板，标题「创建管理员账号」、副题「首次使用，请设置本机管理员凭证」），表单包含三个输入框和一个按钮，从上到下为：

| 元素 | 位置 | 说明 |
| --- | --- | --- |
| 标题「创建管理员账号」 | 表单面板顶部 | 副题「首次使用，请设置本机管理员凭证」 |
| 用户名输入框 | 第一行 | 字段标签「管理员用户名」，占位提示「请输入管理员用户名」，必填 |
| 密码输入框 | 第二行 | 占位提示「请输入密码」，输入框下方常驻辅助文字「不少于 10 位，且同时包含字母和数字」；必填，内容以圆点遮蔽 |
| 确认密码输入框 | 第三行 | 占位提示「请再次输入密码」，必填，内容以圆点遮蔽 |
| 「创建管理员」按钮 | 底部通栏 | 主按钮，提交后进入 loading 状态 |

**操作步骤：**

1. 输入管理员用户名。留空提交会在输入框下方提示「请输入用户名」。
2. 输入密码。密码策略（两条规则，均由表单与后台双重校验）：
   - 长度不低于 10 位，不满足提示「密码不低于 10 位」；
   - 需同时包含字母和数字，不满足提示「密码需同时包含字母和数字」。
3. 再输入一遍密码。两次不一致时提交会弹出错误提示「两次密码不一致」；留空提示「请确认密码」。
4. 点击「创建管理员」。

**预期结果：** 成功时弹出「管理员创建成功」，随后表单整块切换为「保存恢复码」界面（标题「保存恢复码」、副题「忘记密码时的唯一恢复凭证」），这是首次启动必经的第二步：

| 元素 | 说明 |
| --- | --- |
| 警告横幅「请保存恢复码」 | 正文「忘记密码时，需凭恢复码重置。恢复码仅显示一次，若与口令一并遗失将无法恢复访问」 |
| 恢复码码块 | 43 位字符（仅含大小写字母与数字，不含连字符等符号），每 4 位一组以连字符分隔展示（共 11 组）；码块带复制按钮，复制内容即所见展示串（含连字符） |
| 辅助提示 | 「恢复码仅显示一次，关闭后将无法再次查看」 |
| 「我已妥善保存恢复码…」勾选框 | 全句为「我已妥善保存恢复码，并知晓与口令一并遗失将无法恢复访问」；不勾选时下方按钮不可点 |
| 「确认已保存，进入登录」按钮 | 点击后页面自动刷新进入登录界面 |

**边界行为：**

- 管理员只能在首次启动创建。若数据库中已存在账号，再次触发初始化会返回「管理员已初始化，仅首次启动可创建」——正常使用中不会遇到此界面第二次。
- 用户名重复时提示「用户名已存在」。
- 管理员密码同样受上述密码策略约束（后台二次校验，绕过表单直调也会被拒绝）。
- 恢复码与管理员账号同时创建。若创建成功但你还未来得及保存恢复码就退出了应用，登录后可到 设置 → 账号安全 → 「重新生成恢复码」换发新码（需输入当前密码，见 [第 10 章](./10-settings.md)）。

## 日常登录

每次启动灵枢都需要登录（登录态不跨启动保留，关闭应用后下次启动需重新登录）。登录界面为左右双栏：左侧是灵枢产品信息面板（品牌标识、「灵枢 / LinkPivot」字样与拓扑场景动画，底部显示「核心服务正常」状态）；右侧是登录表单，标题「登录灵枢」、副题「进入网络运维工作台」，表单面板底部有「凭证与设备数据均在本机加密存储」的安全提示，其下方显示当前版本号（形如 LinkPivot v1.1.0）。

| 元素 | 位置 | 说明 |
| --- | --- | --- |
| 标题「登录灵枢」 | 表单面板顶部 | 副题「进入网络运维工作台」 |
| 用户名输入框 | 第一行 | 大号输入框（左侧人形图标），占位提示「请输入用户名」，必填 |
| 密码输入框 | 第二行 | 大号输入框（左侧锁形图标），占位提示「请输入密码」，必填，内容以圆点遮蔽 |
| 验证码输入框 | 第三行 | 大号输入框（左侧盾牌图标），占位提示「验证码」，必填 |
| 验证码图片 + 「换一张」按钮 | 第三行右侧 | 左侧为 4 位字符的验证码图片，右侧为带刷新图标的「换一张」按钮；验证码图片加载中显示「加载中」、加载失败显示「加载失败」（可点「换一张」重试） |
| 「登录」按钮 | 底部通栏 | 主按钮，提交后进入 loading 状态 |
| 「忘记密码？」链接 | 「登录」按钮下方居中 | 点击切换到「重置密码」界面（见下节）；重置界面底部有「返回登录」可切回 |

**操作步骤：**

1. 输入用户名、密码。留空时对应输入框会标红要求必填。
2. 查看验证码图片，输入图中的 4 个字符（不区分大小写）。验证码字符集刻意排除了易混淆的 I、O、0、1。
3. 看不清可点击验证码图片本身或「换一张」按钮刷新；刷新后验证码输入框会自动清空。
4. 点击「登录」。

**预期结果：** 成功后进入主界面（见 [第 3 章 界面总览](./03-ui-tour.md)）；若本机管理员账号当前没有有效恢复码（如刚从旧版本升级），会先弹出生成恢复码引导窗（见「升级后首次登录」一节）。

**失败与边界行为：**

| 场景 | 提示文案 | 后续行为 |
| --- | --- | --- |
| 验证码输错/过期 | 「验证码错误」 | 自动刷新验证码并清空验证码输入框 |
| 用户名或密码错误 | 「用户名或密码错误」 | 自动刷新验证码并清空验证码输入框（不提示具体是哪项错，防账号枚举） |
| 连续失败 5 次 | 第 5 次失败当次仍提示「用户名或密码错误」，自锁定期内下一次尝试起提示「登录失败次数过多，请 5 分钟后再试」 | 第 5 次失败发生时该用户名即被锁定 5 分钟，锁定期内即使密码正确也拒绝登录；锁定为内存态，重启应用即清零 |
| 验证码有效期 | 「验证码错误」（过期与输错提示相同，不单独区分） | 每个验证码 5 分钟内有效且只能使用一次 |

> 提示：锁定计数按用户名累计，登录成功一次即清零；验证码输错不计入失败次数。锁定判定在验证码校验之后——锁定期内验证码输错仍先提示「验证码错误」。若你还保有恢复码，也可直接走「忘记密码？」重置——重置成功会同时解除该用户名的登录锁定（见下节）。

## 忘记密码：用恢复码重置

入口在登录界面底部的「忘记密码？」链接（点击后在同一窗口切换视图，不是新开页面）。重置界面同为左右双栏（左侧产品信息面板不变），右侧表单标题「重置密码」、副题「使用恢复码验证身份」。

| 元素 | 说明 |
| --- | --- |
| 用户名输入框 | 占位提示「请输入用户名」，必填 |
| 恢复码输入框 | 占位提示「请输入恢复码（连字符可省略）」；提交时自动去除连字符与空格——照抄展示串或只输字符均可，必填 |
| 新密码输入框 | 与首启同款策略：下方常驻「不少于 10 位，且同时包含字母和数字」，必填，圆点遮蔽 |
| 确认新密码输入框 | 占位提示「请再次输入新密码」；两次不一致提示「两次密码不一致」，必填 |
| 验证码行 | 与登录界面同款：4 位字符验证码图片 + 「换一张」按钮 |
| 「重置密码」按钮 | 底部通栏主按钮 |
| 「返回登录」链接 | 底部居中，切回登录界面 |

**操作步骤：** 输入用户名与恢复码 → 输入符合策略的新密码并确认 → 输入验证码 → 点击「重置密码」。

**失败与边界行为：**

| 场景 | 提示文案 | 后续行为 |
| --- | --- | --- |
| 验证码输错/过期 | 「验证码错误」 | 自动刷新验证码；验证码错误不计入重置失败次数 |
| 恢复码输错 / 该账号未设置恢复码 / 用户名不存在 | 「恢复码错误或未设置」 | 三种情况提示同一文案（不暴露具体错在哪项，防账号探测）；计入重置失败次数 |
| 重置连续失败 5 次 | 第 5 次失败当次仍提示「恢复码错误或未设置」，锁定期内下一次尝试起提示「重置尝试次数过多，请 5 分钟后再试」 | 按用户名独立计数，与登录失败锁定互不影响；内存态，重启应用清零 |
| 新密码不满足策略 | 「密码不低于 10 位」/「密码需同时包含字母和数字」/「两次密码不一致」 | 弱口令不会消耗恢复码（口令校验先于恢复码消费） |

**预期结果：** 成功后表单整块替换为成功视图——大字「密码已重置」、说明「请使用新密码登录」与「返回登录」按钮。注意三点：

1. 重置成功不会自动登录，需返回登录界面用新密码登录；
2. 恢复码是一次性的：重置成功即作废，下次登录会弹出「生成恢复码」引导窗要求重新生成并保存（见下节）；
3. 重置成功会同时解除该用户名的登录失败锁定（若此前因连续输错被锁 5 分钟，不必再等锁过期）。

## 升级后首次登录：生成恢复码引导窗

从旧版本升级后首次登录（或任何「本机管理员账号当前没有有效恢复码」的时刻，例如恢复码刚被重置流程消费掉）时，登录成功后、进入主界面前，会先弹出一个引导窗：

- 标题「生成恢复码」，正文「升级后首次登录，请先为本机管理员账号生成恢复码，用于忘记密码时重置口令」，下方为「生成恢复码」按钮；
- 该窗为阻断式：无关闭按钮，点击蒙层、按 ESC 均不会消失（保证账号始终留有可用恢复码）；此步无需再输密码（它紧邻刚完成的登录认证）；
- 点击「生成恢复码」后，窗内切换为与首启相同的恢复码展示（警告横幅 + 连字符分组码块 + 「我已妥善保存恢复码」勾选门），点「完成」进入主界面；
- 生成失败会就地提示「恢复码生成失败：{原因}」并可在原窗重试，窗口不关闭。

保存好这枚恢复码后，日常登录不会再出现该引导窗（除非恢复码再次被重置消费）。

## 数据存放位置与迁移注意

- 灵枢的全部数据存放在本机用户数据目录（Windows 下为 `%APPDATA%` 中的 `LinkPivot` 目录，形如 `C:\Users\<用户名>\AppData\Roaming\LinkPivot`）中的 SQLite 数据库及相关文件里，不上传云端。
- 设备凭证等敏感字段是加密存储的，加密根密钥绑定本机与本 Windows 账户（原理见 [第 1 章](./01-overview.md)「安全机制通俗说明」）。**只拷贝数据库文件到别的机器是无法解密凭证的**；整机迁移时需连同整个用户数据目录一起迁移，且目标机器使用相同的 Windows 用户账户环境。
- 卸载灵枢不会删除用户数据目录：卸载后 `%APPDATA%\LinkPivot` 仍完整保留，重新安装后数据继续可用；需要彻底清除数据时须手动删除该目录。
- 数据库自带定期备份与升级前安全备份，两类分开滚动保留（双桶轮换）：定期备份默认每 24 小时一次、保留最近 7 份；升级前备份在应用升级迁移数据前自动创建、保留最近 5 份。

## 常见问题

**Q1：忘了管理员密码怎么办？**
在登录界面点「忘记密码？」，用首次启动（或后来重新生成）时保存的恢复码自助重置新密码，流程见上文「忘记密码：用恢复码重置」。注意：恢复码仅显示一次——若恢复码与密码一并遗失，灵枢无法帮你恢复访问，只能从用户数据目录的 backups 备份恢复早期数据库文件，或删除用户数据目录后重新初始化（备份恢复会把数据整体回退到该备份时点、重置则全部清空，此后新增的设备、经验、日志等都会丢失；操作前先完全退出灵枢）。日常建议把密码与恢复码分开存放在安全的密码管理工具中。

**Q2：为什么每次启动都要重新登录？**
登录态保存在内存中，应用关闭即失效，这是桌面安全工具的常见设计：防止他人直接打开你留在电脑上的灵枢就接触到设备凭证与远程通道。

**Q3：密码策略具体是什么？**
不低于 10 位，且需同时包含字母和数字。这是唯一强制的组合规则，特殊字符不强制但允许使用。

**Q4：验证码总是看不清？**
点击验证码图片或「换一张」即可刷新。字符集已排除 I、O、0、1 这四个最易混淆的字符。

**Q5：登录时提示锁定 5 分钟，能立即解锁吗？**
界面内无法直接解锁。等待 5 分钟、重启灵枢（锁定状态存内存，重启即清零），或—if 你保有恢复码—直接走「忘记密码？」重置（重置成功会同时解除登录锁定）。

**Q6：恢复码当时没记下来，还能再看一次吗？**
不能，恢复码出于安全只显示一次。若你仍记得登录密码：到 设置 → 账号安全 → 「重新生成恢复码」（需输入当前密码），旧码作废、换发新码并当场展示一次，这次务必保存（见 [第 10 章](./10-settings.md)）。若密码与恢复码都丢了，见 Q1。
