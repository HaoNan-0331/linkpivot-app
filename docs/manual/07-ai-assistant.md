# 第 7 章 AI 助手

## 功能概述

AI 助手是对话式运维助手：按问题分档预取知识库/经验库/设备上下文，在黑白名单与执行态双重约束下连续自主执行运维命令（越权命令强制人工确认），支持 MCP 工具扩展与经验沉淀（对话一键起草经验、人工确认入库）、生成 Word/Excel 格式的巡检报告文档。多步长任务以 goal 方式推进（进度卡实时呈现，重启后可一键续行）；对 2 台及以上设备的命令巡检自动派发并行子代理批量执行。执行模式与检索行为均可控。AI 的全部执行操作逐条留痕（含命令输出等结果面），每次 AI 调用的请求/响应原文（LLM 报文）默认记录并保留 30 天，均可在日志审计页追溯（见 [第 9 章 日志审计](./09-log-audit.md)）。

每个会话还有一个「执行态」档位：**plan 态（默认，只读调查）**与**执行态（可变更设备）**，详见下文「会话执行态」小节。

使用前提：已在系统设置配置 AI 服务参数（API Key 等，见 [第 10 章](./10-settings.md)）。未配置时进入 AI 助手页显示提示「请先在「系统设置」中配置 AI 服务参数」。

## 界面布局

AI 助手页分为左右两区：

- **左区（会话列表，宽约 220 像素）**：顶部「新建会话」按钮，下方会话条目列表（可滚动）。每条会话一行：未读小圆点（如有）、会话标题、「任务进行中」徽标（如有）、待确认经验数徽标（如有）、右侧删除图标。
- **右区（对话区）**：顶部标题「AI 助手 · 执行态」或「AI 助手 · plan 态」（当前会话执行态标识）与右侧设备上下文选择器；标题下方一条会话 token 状态栏（上下文用量与压缩入口，见下文）；中部消息滚动区（用户气泡右对齐浅蓝、AI 回复全宽裸 markdown、工具调用卡左对齐）；底部输入区（待确认命令在时会整体替换为审批面板）。

**会话切换的隔离保证**：回复进行中切换会话不会串话或丢消息——「思考中」指示只出现在回复所属的会话；切回时在途的步骤卡会完整合并；正在其他会话回答时，当前会话输入框上方显示提示条「AI 正在其他会话回答中，输入已临时锁定」（输入全局锁，防止并发回复互相干扰）。点了「停止」后立刻切换会话再发送同样安全——旧回复晚到的收尾文本不会串进新会话，也不会干扰新一轮回答。

### 会话执行态（plan 态 / 执行态）

每个会话有两档执行态，控制 AI 在本会话里能对设备做什么：

| 档位 | 标题显示 | AI 可做的操作 |
| --- | --- | --- |
| plan 态（默认） | 「AI 助手 · plan 态」 | 只读调查：可执行只读查看类命令（show、display 等），检索资料、分析问题；变更类写命令一律硬拒，AI 会以纯文本输出「变更方案」（自然语言说明 + 待执行命令清单），并告知如何切换到执行态 |
| 执行态 | 「AI 助手 · 执行态」 | 在全局黑白名单与执行模式约束下真正执行命令（含写命令），写命令前按执行模式走确认 |

**切换入口**：输入行首齿轮打开「检索设置」浮层，最下一行「执行态」开关（见下文检索控制）。

- **开（升级到执行态）**：弹出二次确认窗「切换到执行态」，正文说明「执行态下，AI 可对设备执行命令：黑名单命令一律拒绝；智能档免确认词表外命令仍需人工确认，全自动档黑名单外命令直接执行。」并红字提示「写命令可能变更设备配置，请确认本会话需要执行变更操作。」点「确认切换」生效。
- **关（降回 plan 态）**：零确认直接切换；若当时有待确认的命令审批面板，未决命令连带取消（不会执行）。

**执行态生命周期**：执行态授权只在 AI 助手页在场期间有效——切到其他页面（或重启应用）后自动回落为 plan 态（页面级短时授权，避免开着执行态离开后遗忘）。再次需要时重新过二次确认开启。

### 检索控制（输入行行首齿轮图标）

输入行最左侧的小齿轮按钮（无文字），点击向上弹出「检索设置」浮层。前两项设置**全局持久**（跨会话、重启保留），控制 AI 回答前的资料检索行为；第三项「执行态」是当前会话的执行态开关（见上节）：

| 元素 | 位置 | 行为 | 规则与限制 |
| --- | --- | --- | --- |
| 「预取注入」开关 | 浮层第一行 | 开 = 按问题档位在回答前自动检索并注入知识库/经验库/设备上下文；关 = 回答前不做预取（对话区不再出现 [预取] 卡） | 默认关；全局持久 |
| 「补查模式」分段选择 | 浮层第二行 | 「强制补查」= AI 判断资料不足时必定发起补查；「智能补查」= 是否补查由 AI 自行判断 | 默认智能补查；全局持久 |
| 「执行态」开关 | 浮层第三行 | 开 = 升级到执行态（经二次确认弹窗）；关 = 降回 plan 态（零确认） | 按会话生效，不持久（离开 AI 页自动回落 plan）；不受前两项加载失败禁用的影响 |
| 说明三行小字 | 浮层底部 | 「智能模式下由 AI 判断是否补查」「故障排查问题始终强制补查」「执行态下白名单外命令智能档需确认」 | 硬约束：故障排查类问题无论设置如何都强制补查 |

改动即时保存，成功提示「检索设置已更新」。智能补查模式下，AI 决定不查的来源会在回复底部显示灰色标签「未查询：知识库」「未查询：经验库」「未查询：设备」等——不是出错，是「智能模式下由 AI 判断」的知情呈现；强制补查模式下不会出现这些标签。

**换词重查**（智能/强制两模式统一行为）：补查时若 AI 给出的检索关键词与本次对话已查过且未命中的关键词相同，系统不会用同一个词再查一遍，而是追加一轮「换词请求」要求 AI 换更具体的关键词重查。此时回复中会出现系统说明「知识库已用关键词 “xxx” 检索未命中，已请求换词重查」（经验库同理）。换词只发生一次——若换词后关键词仍与已查词相同，显示「本次不再检索（换词有界防循环）」，AI 以现有资料作答。

### 会话 token 状态栏与上下文压缩

对话区标题下方常驻一条状态栏（Claude Code 底栏形态），从左到右：**模型名 │ 块状进度条 + 百分比 │ 本轮 token（含缓存命中）│ 会话累计 │ 窗口容量**，行尾「手动压缩」文字按钮。

| 字段 | 含义 |
| --- | --- |
| 模型名 | 当前配置的 AI 模型名称 |
| 块状进度条 + 百分比 | 会话已占用 token 相对压缩阈值的比例（10 段块条，填充段 = 已用占比；达到 100% 即将触发自动压缩） |
| 本轮 token（缓存 N） | 最近一次 AI 调用消耗的 token，括号内为缓存命中部分（部分服务商对重复上下文按更低价格计费） |
| 会话累计 | 本会话累计占用的上下文 token |
| 窗口 | 所配模型的上下文窗口容量 |

- 进度条与百分比按占比三态变色：占比超 60% 转警示黄、超 80% 转警示红（达到压缩阈值线即呈红色——即将压缩的运行态提示，不是错误）。
- 状态栏数据在会话加载、每轮回复结束、压缩发生后刷新。**升级前创建的旧版会话没有事件流数据**，状态栏数值位显示「—」、进度条为空槽、手动压缩按钮禁用。
- 「手动压缩」按钮在 AI 回复进行中或压缩进行中禁用（悬停提示「AI 回复中或压缩进行中」）。

**上下文压缩是什么**：长会话的上下文接近窗口上限时，系统把较早的消息交给 AI 摘要成一份「检查点」，被摘要覆盖的旧消息从上下文中让位——AI 的记忆被压缩，但对话不中断、历史消息仍在界面上可查。触发方式三种：

- **自动（预防性压缩）**：会话 token 达到压缩阈值（默认为窗口的 80%，可在系统设置调小，见 [第 10 章](./10-settings.md)）时在回答前自动压缩。
- **自动（超限压缩）**：上下文超出模型窗口上限被服务方拒绝时，自动强制压缩后重试（用户无需干预）。
- **手动压缩**：点状态栏「手动压缩」，弹出确认弹窗。

**手动压缩弹窗**（每次都弹，无「不再询问」）：

- 可压缩时显示三行预估：当前会话 token、预计压缩范围（被遮蔽约 N 条消息 · 保留尾部约 N token）、预计节省约 N token；
- 内容不足时告知「保留尾部量约 N token——会话内容需超过此量才会产生可压缩范围，当前全部内容都在保留区内，压缩不会减少上下文」，并给出指引「可继续对话累积上下文，或在 系统设置 → AI 调小「上下文压缩阈值」后再试」（「开始压缩」按钮禁用）；
- 下方备注框「压缩要求/备注（可空）」可填写对本次摘要的额外要求（最长 500 字，每次打开自动清空）；
- 点「开始压缩」执行，成功提示「压缩完成」，失败弹错误可重试。

**压缩检查点卡**：压缩完成后，消息流中插入一张中性色检查点卡——头行「上下文已压缩」、元信息行「已压缩 N 条消息 · 约 N token · 预防性压缩/超限压缩/手动压缩」，默认折叠，点开可查看 AI 生成的摘要全文（按八个方面组织的检查点，是 AI 后续对话的记忆锚点）。被压缩的旧消息从 AI 的上下文中让位，但仍在界面上正常显示。

### 对话区消息

**消息形态**（不对称布局）：

- goal 进度卡：AI 多步任务（goal）推进时实时刷新的进度卡（见下文「goal 进度卡」）。
- 批量巡检组卡：多台设备派发子代理巡检时的逐台汇总卡（见下文「批量巡检组卡」）。

- 灰色「未查询实时数据」：本轮明确没有查询任何实时数据（零检索零执行的诚实声明）；
- 灰色「未查询：{来源}」：智能补查模式下 AI 决定不查的来源逐个标注；
- 灰色小字补查记录：补查未命中或设备未查的知情说明。

**硬停提示条**（黄色）：任务被手动停止时显示「任务进行中被手动停止，未生成总结；已执行步骤保留在上方。」

**终轮对账警示条**（黄色）：AI 回复声称做了操作、但系统审计发现本轮没有任何命令执行记录时，回复底部显示「⚠ 本轮无命令执行记录（系统审计）」。该判定由系统对账产生（AI 正文无法伪造），提示你这条回复的执行声称没有事实依据。

**思考中指示**：回复进行中显示「思考中…」扫字动画；AI 自主任务（agent）运行中旁边常驻红色「停止」小按钮——点击立即中止，无二次确认。多步任务在后台推进时（输入区空闲、任务由后台驱动轮执行）停止按钮同样常驻，可随时中止。

### 工具调用卡（步骤卡）

AI 的每个动作（执行命令/检索知识库/检索经验库/调用 MCP 工具）显示为一张 24 像素高的单行卡：左侧状态图标或状态点 → 状态词 → 动作标题 → 单行截断摘要 → 行尾时间。点击整行（或聚焦后按 Enter/Space）原地展开为上下两个区：调用参数（IN）与原始结果（OUT），各自独立滚动。

**状态七态**：

| 状态词 | 含义 |
| --- | --- |
| 执行中 | 正在执行（带扫光动画） |
| 重试中 | 失败后自动重试（带扫光动画） |
| 完成 | 成功结束 |
| 失败 | 执行出错（仅状态词与摘要红字，卡片本身不变红） |
| 已熔断 | 连续失败次数过多被熔断保护 |
| 冷却中 | 熔断后的冷却等待 |
| 已中断 | 被用户停止或会话中断 |

旧格式记录无七态信息时按结果映射为「完成/超时/失败」（「超时」是旧格式记录的映射标签，不在七态之列）。超时的固定原因文案：「工具服务 60 秒内未响应，已自动中断」。

**失败追踪短码**：失败或超时的卡，摘要尾部附 8 位追踪短码「（追踪 xxxxxxxx）」（展开后的失败说明行同样携带）。这是该次失败的审计定位号——报障时提供此号，或在 [第 9 章](./09-log-audit.md) 日志审计页的关键词框粘贴短码，即可直接定位对应的执行记录与关联日志。

**动作标题**（可带前缀与通道后缀）：

- 「[预取] 检索知识库」「[预取] 检索经验库」：回答前的分档预取；
- 「[补查] 检索知识库」等：回答中途的补充检索；
- 「在 {设备名} 执行命令 · SSH」（或 · TELNET）：设备命令，后缀标明执行通道；
- 「调用工具 {工具名}」：MCP 工具调用。

**核对结论行**（仅命令执行卡）：AI 执行写命令后，系统自动抓取该设备的配置快照做前后比对，结论以一行小字常显在卡片头行下方（折叠态可见，由系统写入，AI 无法谎报）：

| 结论 | 颜色 | 含义 |
| --- | --- | --- |
| 「✓ 配置变更已核实」 | 绿 | 命令声明的变更已在设备配置中核实生效 |
| 「⚠ 快照不符：未见预期变更」 | 黄 | 命令执行成功，但配置中未见预期变更（断言与事实不符） |
| 「此通道无快照」 | 灰 | 该通道不支持配置快照（如 Telnet/部分 Windows 场景），无从核对 |
| 「⚠ 后快照缺失，待下次写命令补比对」 | 黄 | 执行后快照抓取失败，下次写命令时会自动补比对 |

### 文档附件卡

让 AI 生成巡检报告等文档（如「把刚才的排查结果生成一份 Word 报告」）后，消息流中插入一张两行紧凑卡：类型图标（Word 蓝色 / Excel 绿色）+ 报告主题 + 「打开文件夹」「导出」两个按钮；第二行元信息「{Word 文档/Excel 表格} · v{N} · 生成于 {时间} · 基于 {N} 条命令输出」（悬停时间可看完整时间戳，悬停元信息行可看来源摘要——N 只来自系统统计，不信 AI 自述）。

- 「导出」：弹出另存为对话框，把文档快照复制到你选的位置，成功提示「文档已导出：{路径}」；
- 「打开文件夹」：在资源管理器中定位该文档；快照已被清理（超过保留期）时提示「文件不存在或已被清理，可让 AI 重新生成该文档」；
- 点卡片本体无动作（刻意设计——卡片不可点开，避免误导）。

文档快照按会话存放在本机沙箱目录，占用与清理见 [第 10 章](./10-settings.md)「沙箱文档存储」卡。

### goal 进度卡（多步任务）

AI 执行跨多轮的长任务（如「给这 10 台交换机做版本核对，异常的先给我方案」）时，会先建立 goal（任务目标：从你的请求提炼的一句话目标 + 步骤清单 + 轮数预算），此后每轮推进都实时刷新同一张进度卡。同一任务至多一张卡（携带最新状态，不逐轮刷屏）；任务结束后卡保留为终态记录，重开会话仍可回看。

卡结构（自上而下，全部常显不折叠——实时进度面，与压缩检查点卡的折叠设计刻意不同）：

| 区域 | 内容 |
| --- | --- |
| 头行 | 目标图标 + 任务目标文字（超长省略号截断，悬停看全文）+ 状态词 + 行尾时间 |
| meta 行 | 「Round {当前轮}/{轮数预算}」；任务带步骤清单时附「 · 步骤 {已完成}/{总数}」（无步骤的目标该段省略） |
| 受阻原因行 | 仅「已受阻」态出现：「受阻原因：{原因}」（行尾可附 8 位追踪短码「（追踪 xxxxxxxx）」，到 [第 9 章](./09-log-audit.md) 日志审计页可按号定位该次失败） |
| 步骤列表 | AI 制定的步骤清单逐行呈现，三态图标：待开始（时钟图标，灰）/ 进行中（三角图标，蓝，当前步唯一强调位）/ 已完成（对勾图标，绿）；清单超长时卡内滚动，不撑高消息流 |
| 「继续」按钮 | 条件出现（见下），卡右下角蓝色主按钮 |

**状态词五态**：

| 状态词 | 含义 |
| --- | --- |
| 进行中 | 任务正在执行 |
| 等待续行 | 执行停摆等待你授权续行——应用重启或会话恢复后进入此态（上下文压缩后的自动续行不经过此态） |
| 已暂停 | 被手动停止：点「停止」后任务自动收口为暂停，进度不丢失 |
| 已受阻 | AI 连续多轮报告无法推进，任务收口；发新消息可自然推动新任务 |
| 已完成 | 任务目标达成（AI 标记完成前，系统强制所有非空步骤先标记完成——不会出现「已完成但步骤未做完」的矛盾显示） |

**「继续」按钮（重启续行）**：应用重启（或会话恢复）后，执行中的任务不会自动跑——进度卡变为「等待续行」，点「继续」即从原进度续跑。续行授权不持久化是安全设计：每次重启后都需要你亲手点一次，AI 不会在你不在场时自行恢复执行。按钮出现条件：等待续行或已暂停（已完成/已受阻不出现——受阻的出路是发新消息，不给绕过按钮）；点击中转圈防连点；成功后按钮消失、状态词变回「进行中」。

轮数预算默认 256 轮（创建任务时确定，可在系统设置「任务最大轮数」调整，见 [第 10 章](./10-settings.md)）；卡内容全部由系统按结构化数据写入，AI 正文无法伪造。

### 批量巡检组卡

对 2 台及以上设备发起命令巡检（如「巡检这 5 台交换机，核对版本、接口错包和告警」）时，AI 不在对话里逐台执行刷屏，而是一次性派发并行子代理：每台设备绑定一个独立子代理会话执行巡检命令，父会话只收每台设备的结构化摘要。同一次巡检至多一张组卡，设备状态逐台实时更新（并行台数由系统设置「巡检并发数」控制，默认 4 台，见 [第 10 章](./10-settings.md)）。

卡结构（自上而下）：

| 区域 | 内容 |
| --- | --- |
| 头行 | 组件图标 +「批量巡检」+ 行尾时间 |
| 进度行（进行中） | 「已完成 {x}/{总台数} 台 · {y} 台执行中」，有排队时附「 · {z} 台排队」 |
| 汇总行（终态） | 「巡检完成 · 成功 {a} 台 · 失败 {b} 台 · 超时 {c} 台」——失败/超时为零的段省略；有失败或超时台时整行转警示黄 |
| 设备行 | 每台一行：状态图标 + 设备名 +「{N} 条命令」+ 状态词（失败/超时台的状态词后可附追踪短码「（追踪 xxxxxxxx）」，供报障与日志审计按号定位）；行间虚线分隔，清单超长卡内滚动 |
| 异常副行 | 该台发现异常时显示「异常：{摘要}」（无异常不显示——异常栏只写真异常，不拿正常总结填充） |
| 关键输出副行 | 「关键输出：」+ 等宽字体逐行展示的命令输出摘录（至多 3 行） |

设备状态词五种：排队中（等待并发空位）/ 执行中 / 成功 / 失败 / 超时。

组卡零交互只读（无按钮无确认面——子代理只执行只读巡检命令，写命令在子代理工具面根本不暴露，不产生待确认命令）；某台设备故障或超时只隔离该台（标「失败/超时」），不卡死其余设备；全部完成后 AI 基于逐台摘要给出巡检结论。

**派发规则**：单批至多 50 台——超出的派发调用会被丢弃并要求 AI 拆分为多批重发；混合巡检（部分设备要求走 MCP 工具，如防火墙 MCP 接口）时两路并行：命令巡检部分照常派发子代理，MCP 巡检部分由 AI 在会话中逐台调用 MCP 工具完成，互不阻塞；单台设备的命令查看不派发，仍走普通命令执行。子代理会话不进会话列表——组卡是唯一查看面。

### 编造拦截卡

AI 的回复中声称「已完成某操作」但本轮并没有对应执行记录时，系统会拦截这条回复（不让它直接展示），改为插入一张黄色警示卡并要求 AI 重新作答：

- 头行「已拦截的编造回复」+ 说明「该回复含执行断言但无实际执行记录，系统已拦截并要求 AI 重新作答」；
- 中段逐字保留被拦截的原文（纯文本展示，不经排版渲染——审计优先）；
- 末段「系统质询」展示系统发给 AI 的质询全文；
- 卡片只读（处置全自动：拦截 → 质询 → 重答），修正后的回复作为正常 AI 消息跟随其后。

这是「承诺-兑现」检测机制的用户可见面：AI 说做了什么，必须真有执行记录佐证。

### 命令审批面板（待确认命令出现时替换输入区）

当 AI 提议的命令需要确认时，输入区被琥珀色描边的审批面板接管（面板不消失无法继续对话）。结构：顶部琥珀条「等待审批」（左侧圆点）→ 可滚动命令区（最高约 336 像素，键盘可 Tab 进入滚动）→ 底部按钮行。面板左缘常显静态提示「{N} 分钟内未处理将自动拒绝」（N 为设置的审批超时时限，默认 10 分钟，见 [第 10 章](./10-settings.md)）。

**普通确认分支**（「每次确认」档的全部命令，或「智能」档免确认词表外的命令）：

- AI 说明段：AI 解释为什么要执行这些命令；
- 「待执行命令:」小节：逐条列出「[设备名] 命令原文」（等宽字体）；AI 对单条命令附有说明时，命令下方以灰色小字显示该命令的理由（AI 为什么提议这一条）；
- 「已拒绝命令:」小节（如有）：校验未过被自动拒绝的命令与拒绝原因（不会执行）。

**越权确认分支**（命令命中越权防护规则时，警示更强）：

- 标题「越权确认（N 条命中 / 共 M 条命令）」；
- 「AI 命令命中 N 条安全规则，请核对目标后确认：」；
- 「预期目标 / 实际目标」对照卡：左侧是你选定的设备范围，右侧是命令实际指向的目标，不一致正是越权拦截的意义（三类典型场景：命令目标超出对话所选设备集、AI 发生设备跳转、MCP 工具参数携带敏感目标）；
- 命中规则列表：规则编号标签（红色=高危级、金色=一般越权级）+ 规则解释 + 对应命令原文（红底等宽展示）；
- 「常规命令（无越权风险）」分节：同一批中未命中的命令（蓝标签）；
- 「已拒绝命令（N 条，不会执行）」分节（如有）。

**按钮**（面板唯一出口，无任何绕过入口）：

- 「拒绝执行」：拒绝全部待执行命令（静止时中性色，悬停变红）；
- 「确认执行」：放行待执行命令（越权场景下点击即视为「用户确认放行」，会记入日志审计）；
- 提交期间两按钮均转圈禁用。

**审批超时**：面板放置超过设定时限（默认 10 分钟）未处理，系统自动按拒绝收尾——面板消失，消息流插入系统提示条「审批超时已自动拒绝」，相关日志记为已拒绝。这是防止待确认命令无限挂起的兜底。

**挂起面板跨重启恢复**：审批时限从命令挂起时刻连续计算，重启应用不重置——重启后仍在时限内的待确认面板会自动恢复（切回该会话即见），可继续「确认执行」或「拒绝执行」，恢复批次的确认走完整校验（越权/黑名单/执行态闸不因恢复而豁免）；已超时才重启回来的，面板不恢复，直接按「审批超时」自动拒绝收尾（消息流有系统提示条可查）。

审批结果与全部执行留痕可在 [第 9 章 日志审计](./09-log-audit.md) 追溯：AI 在本页的每一条命令——含子代理巡检命令、MCP 工具调用、只读检索与沙箱执行——无论成败都逐条入「AI 助手执行日志」，命令输出、耗时、退出码等结果面一并加密落库；越权确认的放行/取消在「越权记录」视图单独可查；每次 AI 调用发送给大模型的完整请求与返回的原始响应（LLM 报文，含 system prompt 与历史消息，默认记录、保留 30 天）可在执行日志详情弹窗末尾的「LLM 报文」折叠区与「LLM 报文」页签查看。

### @ 引用（设备 / 拓扑）

在输入框中键入 `@` 弹出引用候选浮层，选中后以 `@名称` 形态插入消息。发送后，系统把被引用设备/拓扑的当前资料（有界快照）注入 AI 上下文——AI 无需你重复描述就能直接知道那台设备的 IP、类型等信息，或那张拓扑的构成。

| 规则 | 说明 |
| --- | --- |
| 候选分组 | 两组：设备（最多 8 条，显示「名称（IP）」）与拓扑（最多 5 条）；组头「设备」「拓扑」为灰显标题不可选 |
| 过滤 | 键入 @ 后继续输入即按前缀过滤，匹配设备名称或 IP、拓扑名称（大小写不敏感的子串匹配） |
| 零候选不弹层 | 没有匹配项时不会出现空弹层（输入 `@` 后无匹配或匹配词为空，直接继续正常输入） |
| 含空格的名称 | 引用带空格的名称自动用引号包裹（`@"核心 交换机"` 形态），发送与解析两侧同一语法 |
| 不误触发 | `@` 前一个字符是字母/数字/点/下划线等（邮箱地址、文件路径里的 @）不会触发候选——在邮箱或路径中间打 @ 不会弹出浮层 |
| 弹层中的键盘操作 | ↑↓ 选择、Enter 选中插入；候选弹层打开时 Shift+Enter 选候选属于已知边界（归 Enter 族），想换行先按 ESC 关闭弹层 |

### 经验起草与确认流

**第一步：发起起草。**会话结束后点「经验总结」。AI 两阶段起草：先从对话提取候选经验（含查重比对——与同类目同设备的既有经验对比，判断是新增还是更新），再对候选做复核裁决。起草完成后自动弹出确认弹窗。

**第二步：人工确认（红线：AI 产出必经人工确认才入经验库）。**确认弹窗为宽幅左右分栏：

- 左栏草稿列表：每条草稿一个勾选框（默认全部「采纳」，可改为「丢弃」）；标签标注分类与「新增/更新」性质；质量门未过（缺必填项）的草稿标红显示缺失项（如「缺 严重程度」）；更新类草稿另有「标失效旧条目」勾选框（默认不勾——勾选后采纳时才把同主题旧经验标记为失效，避免 AI 误判更新时误伤旧条目）。
- 右栏编辑表单：选中草稿的字段可逐项修改（与 [第 8 章](./08-knowledge-base.md) 经验表单同构：标题/分类/内容/标签/严重程度/故障现象/根本原因/解决办法/预防措施/关联设备），并可「查看原始会话」核对依据。
- 底部按钮：「全选采纳」「全选删除」快捷操作，以及「确认采纳 N 条 + 删除 M 条」批量提交（单次原子提交，任一条失败整体回滚）。

确认后的经验立即可被 AI 检索复用；丢弃的草稿删除。有未确认草稿时（关掉了弹窗），随时点输入区「待确认 N 条」回来处理。待确认草稿按会话隔离：起草完成自动弹出的弹窗只列本轮产出的草稿，从「待确认 N 条」重开时只列当前会话的全部待确认草稿；其他会话的待确认草稿不会混入——会话列表各会话的数字徽标提示其所在，切到对应会话即可处理。

### MCP 工具调用

选中带 MCP 绑定的设备（「可调MCP」标签）后，AI 可调用该设备的 MCP 工具。工具调用同样显示为工具调用卡（标题「调用工具 {工具名}」），高风险工具参数会触发与命令同级的确认流。MCP 连接器与包的配置见 [第 10 章](./10-settings.md)。

## 典型流程一：故障排查问答

1. 点「新建会话」。预期左侧出现新会话条目并选中，对话区显示空态「向 AI 助手提问，选择设备后可查询设备信息」。
2. 点右上设备选择器，勾选故障设备（绿色「可执行」标签）。预期收起态摘要显示「已选：{设备名}」。
3. 在输入框描述现象（如「核心交换机-01 的 Gi0/0/1 口频繁 Up/Down，帮我看下原因」），点「发送」。预期消息以浅蓝气泡出现在右侧，随后出现「思考中…」与若干 [预取] 步骤卡。
4. 等待回复完成。预期 AI 回复顶部显示「故障排查」分档标签；若开了预取，回复引用知识库/经验库内容（参考来源区可点开核对）；智能补查模式下若 AI 未查某来源，底部出现对应「未查询：…」灰标签。
5. 追问或让 AI 执行确认命令（进入典型流程二）。

## 典型流程二：让 AI 执行命令

1. 确保目标设备「可执行」、会话已切到执行态（齿轮 → 执行态开关开，见「会话执行态」），且命令首词不在黑名单（词表维护见 [第 10 章](./10-settings.md)）。
2. 对 AI 下达操作意图（如「查看核心交换机-01 的接口流量」）。预期 AI 生成命令提议：
   - 需要确认时：出现审批面板（普通分支），核对「待执行命令」后点「确认执行」；预期面板消失，步骤卡转为「执行中 → 完成」，AI 随后解读输出；写命令的步骤卡下方还会出现核对结论行。
   - 越权命中：面板升级为越权分支（预期目标/实际目标对照），核对差异后「拒绝执行」或「确认执行」。
3. 需要中止时点「停止」红色小按钮。预期立即停止，尾部出现黄色硬停提示条。
4. 事后到日志审计页追溯本次执行的完整记录（[第 9 章](./09-log-audit.md)）：可按时间/状态/设备筛选，或粘贴失败卡尾部的追踪短码直接定位；需要一字不差的调用现场时，展开记录详情末尾的「LLM 报文」折叠区。

## 典型流程三：沉淀经验

1. 处理完一个有价值的问题后，点「经验总结」。预期按钮转圈，AI 两阶段起草后自动弹出确认弹窗。
2. 左栏逐条决策：默认采纳；不想要的改为「丢弃」；质量门标红的草稿先在右栏补全必填项（缺项时提交按钮禁用）。
3. 更新类草稿按需勾选「标失效旧条目」（确认要让旧经验失效才勾）。
4. 点「确认采纳 N 条 + 删除 M 条」。预期提示成功，草稿进入经验库（有效状态），输入区「待确认 N 条」消失。
5. 下次同类问题，AI 会检索到这条经验——回复的「📗 经验 ×1」徽章即复用凭证，点击可回看。

## 典型流程四：批量巡检多台设备

1. 点「新建会话」，在设备选择器勾选要巡检的多台设备（如 5 台接入交换机）。
2. 在输入框下达巡检意图（如「巡检这几台交换机，核对版本、接口错包和告警，有异常的汇总给我」），点「发送」。
3. 预期 AI 建立多步任务并插入 goal 进度卡，随后插入「批量巡检」组卡：每台设备一行，状态从「排队中/执行中」逐台翻为「成功/失败/超时」，有异常的设备带「异常：…」副行与关键输出摘录。
4. 巡检命令走子代理只读白名单区直接执行，不产生审批面板；若同一任务还要求了需确认的操作（如在个别设备上执行写命令），这些仍在会话中照常走审批（确认规则与单台执行一致）。
5. 全部完成后组卡汇总行显示「巡检完成 · 成功 N 台 · 失败 M 台…」，AI 给出逐台结论与建议。期间关闭了应用的话，重开会话在 goal 进度卡点「继续」可续跑未完成的任务。

## Agent 工作方式说明

AI 的自主执行（agent）不是单轮问答，而是受控循环：检索资料 → 生成动作 → 执行 → 依据结果决定下一步，直到给出总结或触发保护。理解以下机制有助于解读界面现象：

| 机制 | 界面表现 | 设计目的 |
| --- | --- | --- |
| 分档预取 | 回复前的 [预取] 步骤卡 + 分档标签 | 按问题类型只取必要资料，控制成本与噪声 |
| 补查 | 中途的 [补查] 步骤卡 | 初次资料不足时补齐依据 |
| @引用注入 | 输入框 @ 候选与消息中的 `@名称` | 把指定设备/拓扑的资料精准带入上下文 |
| 执行态闸 | 标题「plan 态/执行态」+ 检索面板执行态开关 | plan 会话只读调查，写操作必须显式提权 |
| 黑白名单校验 | 审批面板「已拒绝命令」小节 | 命令安全的第一道闸（黑名单任何档位硬拒） |
| 越权防护 | 越权确认分支 + 日志「越权记录」 | 目标偏移强制人工把关 |
| 熔断/冷却 | 「已熔断」「冷却中」状态词 | 防止持续冲击故障设备 |
| 硬顶收尾 | 循环停止 + 诚实说明 | 步数与上下文 Token 预算超限即停，不无限消耗 |
| 上下文压缩 | token 状态栏 + 压缩检查点卡 | 长会话自动/手动摘要旧消息，防止上下文超窗 |
| 编造拦截 | 「已拦截的编造回复」警示卡 | AI 声称执行必须有真实执行记录佐证 |
| 配置核对 | 执行卡「核对结论行」四态 | 写命令后前后快照比对，变更是否生效有据可查 |
| 纠偏递进 | 同设备连续失败 3 次后 AI 换方法、6 次终止 | 防止 AI 对同一故障反复用同一招硬撞 |
| 来源徽章 | 📚/📗/🔧 徽章与明细 | 回答依据可追溯、可点击核对 |
| goal 多步任务 | goal 进度卡（Round/步骤/状态词）+「继续」按钮 | 长任务有明确目标、步骤与轮数预算；重启停摆需人工续行（续行授权不持久化） |
| 批量巡检派发 | 「批量巡检」组卡逐台实时更新 | 2 台及以上命令巡检派发并行子代理，多台原始输出不淹没会话上下文；单台仍逐条执行 |
| 审批挂起恢复 | 重启后时限内的审批面板自动恢复 | 挂起命令的生命周期由审批超时唯一决定，时限连续计算不因重启重置 |
| 全量审计留痕 | 失败卡「（追踪 xxxxxxxx）」短码 + 日志审计页（第 9 章） | 执行记录与 LLM 报文全量落库——AI 干了什么、依据什么、结果如何可全程回查 |

## 规则与限制

| 规则 | 说明 |
| --- | --- |
| 使用门槛 | 未配置 AI 服务参数时整页只显示引导提示，不加载会话 |
| 会话执行态 | 每会话 plan（默认，只读调查：写命令硬拒，AI 输出变更方案文本）或执行态（经二次确认升级；可真正执行命令）。执行态授权页面级短时有效：离开 AI 页或重启自动回落 plan，回落时未决确认批次连带取消 |
| 命令裁决链 | AI 提议的每条命令按序校验：结构校验 → 黑名单首词（任何执行模式与执行态下一律硬拒）→ 设备级策略（见第 5 章命令策略）→ 全局词表 → 越权检测 → 执行模式分派。plan 态下写命令在裁决层直接拒绝，与提示词无关 |
| 词表外命令分派 | 执行态下，免确认词表/白名单外的命令：每次确认档弹窗、智能档弹窗确认、全自动档直接执行；词表内命令：每次确认档仍弹窗、智能/全自动档直接执行（分档说明见第 10 章执行模式卡） |
| 越权强制确认 | 越权拦截不受执行态与执行模式影响——全自动模式下越权命令照样强制打断确认（日志中标识「自动拦截」） |
| 执行模式 | confirm（每批确认）/ smart（智能）/ auto（自动），在系统设置配置（见第 10 章） |
| Agent 硬顶 | 自主任务有硬顶（步数上限、同命令连续失败熔断、失败冷却、上下文 Token 预算——预算随压缩阈值与窗口联动），触顶诚实收尾不无限循环 |
| 上下文压缩 | 会话 token 达阈值（默认窗口 80%）自动预防性压缩、超窗自动超限压缩、可手动压缩；压缩产出检查点卡，被遮蔽消息退出 AI 上下文但界面保留 |
| 编造拦截 | 回复含执行断言但无执行记录时整体拦截并质询重答（终轮另有「⚠ 本轮无命令执行记录（系统审计）」对账警示条） |
| 配置核对 | 执行态下写命令自动前后抓取配置快照比对，结论行四态（已核实/不符/无快照/后快照缺失）由系统写入不可伪造 |
| 纠偏递进 | 同一设备上 AI 连续失败 3 次系统注入提醒要求换方法，达 6 次上限终止任务 |
| goal 多步任务 | 每会话同一时刻至多一个当前任务；Round 有预算上限（创建时确定，默认 256 轮，可配见第 10 章「任务最大轮数」）；连续多轮受阻自动收口为「已受阻」；续行授权不持久化——重启后停摆任务需手动点「继续」续跑 |
| 批量巡检子代理 | 2 台及以上设备的命令巡检必须经子代理并行派发（禁止父会话逐台执行刷屏），单台设备仍逐条执行；单批至多 50 台，超限丢弃并要求拆分；子代理工具面只读（写命令在定义层不暴露）、单台失败/超时隔离不卡整批；子代理会话不进会话列表 |
| 审批超时 | 待确认命令超过设定时限（默认 10 分钟，可配）自动按拒绝收尾，系统提示条告知 |
| 审批挂起恢复 | 审批时限从命令挂起时刻连续计算，重启应用不重置——重启后仍在时限内的待确认面板自动恢复（切回该会话即见）；超时重启的按「审批超时」收尾；恢复批次的确认走完整校验（越权/黑名单/执行态闸零豁免） |
| 审计留痕 | AI 在本页的全部执行（命令/子代理巡检/MCP 工具/只读检索/沙箱）逐条入执行日志，成功失败都记，命令输出、耗时、退出码等结果面一并加密落库；每次 AI 调用的请求/响应原文入 LLM 报文（默认开启，保留 30 天）——查询入口与筛选见第 9 章 |
| 追踪短码 | 失败信息统一携带 8 位短码「（追踪 xxxxxxxx）」：工具卡失败态、goal 卡受阻原因行、巡检组卡失败/超时设备行；报障提供此号即可按号定位全链路日志，日志审计页关键词框支持粘贴短码直查 |
| 熔断保护 | 连续失败过多自动熔断进入冷却，防止对故障设备持续冲击 |
| 输入全局锁 | 一条回复在途时全应用输入锁定（提示条说明原因），防止并发回复竞态 |
| 会话隔离 | 消息、在途步骤卡、思考中指示严格按会话归属，切换不串话不丢失；停止回复后立刻切会话再发送，旧回复晚到的收尾同样不会串入新会话 |
| 经验确认红线 | AI 起草的经验必须人工确认后才发布；手动录入不受此限 |
| 待确认草稿会话隔离 | 经验草稿按来源会话归属：「待确认 N 条」入口与确认弹窗只列当前会话的草稿；会话列表徽标分会话显示各自待确认数 |
| 检索设置持久 | 预取开关与补查模式全局持久；故障排查档恒强制补查不可关闭 |
| 换词重查 | 同词已查未命中不重复检索，改为要求 AI 换更具体关键词重查一次；换词后仍同词则告知不再检索（单次有界防循环），智能/强制模式统一 |
| 停止语义 | 停止按钮立即中止（无确认）；已执行步骤保留展示，尾部显示硬停提示条 |
| 旧版会话限制 | 升级前创建的旧版会话无事件流数据：token 状态栏显示「—」、不可手动压缩；其消息正常显示，被引用查看时明确提示不可查 |

## 常见问题

**Q1：AI 不执行命令，只给文字回答？**
检查四点：会话是否在执行态（plan 态下写命令被拒，AI 会给变更方案文本——按方案里的指引切换执行态）；设备是否选了「可执行」档（仅问答设备不能执行）；命令首词是否命中黑名单或在词表外被当前模式拒绝（被拒命令会在审批面板「已拒绝命令」或步骤卡中说明）；执行模式与审批流程是否走完（审批面板等待你点「确认执行」）。

**Q2：回复下面出现灰色「未查询：设备」标签？**
这是智能补查模式的知情呈现：AI 判断无需查设备实时数据。想要必定补查，把补查模式切到「强制补查」。

**Q3：审批面板一直占着输入框？**
在当前会话里必须处理完才消失——点「确认执行」放行，或点「拒绝执行」拒绝；切换会话会关闭面板、离开 AI 助手页则按拒绝处理，两种情况下未决命令都不会执行（重启应用则见 Q26：时限内面板会恢复）。这是设计如此：不点「确认执行」，命令没有任何被执行的途径。

**Q4：切到别的会话再回来，回复还在吗？**
在。回复严格归属其会话：切走时步骤卡暂存，切回合并显示；完成后的消息与轨迹永久保存在会话历史中。

**Q5：「经验总结」点了没反应？**
会话需有内容（空会话按钮禁用）；起草过程可能较长（两阶段 AI 处理），按钮转圈期间请等待；完成后确认弹窗自动弹出。

**Q6：AI 回复的表格/代码显示乱？**
AI 回复按 markdown 渲染；极少情况下模型输出不规范 markdown 会导致排版异常，重问一次通常恢复。

**Q7：怎么让 AI 别再问我确认，直接执行？**
两步：先把会话切到执行态（plan 态只读，不会执行任何写命令），再到系统设置把执行模式改为「全自动」（理解越权命令与黑名单仍会拦截/强制确认——这是安全底线不可关闭）。日常工作流建议保持每次确认或智能。

**Q8：停止后 AI 的半成品回答去哪了？**
已执行步骤保留在消息区，尾部黄条说明「任务进行中被手动停止，未生成总结；已执行步骤保留在上方。」重新提问即可继续。

**Q9：删除会话会连带删掉已确认的经验吗？**
不会。经验一旦确认入库就是独立资产；删除会话只删对话记录。经验的来源会话引用将无法再回看原文。

**Q10：为什么同一个问题两次回答引用的资料不一样？**
检索命中与 AI 判断（智能补查模式）随知识库内容、经验库状态与提问措辞变化；用「参考来源」与徽章核对每次的具体依据即可。

**Q11：多选了 10 台以上设备有什么后果？**
选择器会提示「设备较多，AI 回答质量可能下降」——上下文过多会稀释重点，建议按问题聚焦到相关设备子集。

**Q12：「已熔断」之后还能继续让 AI 执行吗？**
冷却结束后自动恢复；若设备持续故障，先处理设备问题再让 AI 重试，避免反复触发熔断。

**Q13：AI 助手页提示「请先在「系统设置」中配置 AI 服务参数」？**
说明尚未配置模型服务。到系统设置 → AI 配置完成 API 地址与 Key 后回到本页即可正常使用（配置步骤见第 10 章）。

**Q14：会话标题能改吗？**
标题由首条提问自动生成，当前版本不提供手动改名；按内容可辨识为主。

**Q15：回复里出现「已请求换词重查」是什么意思？**
补查时 AI 想用的关键词与之前查过（且未命中）的相同，系统会让 AI 换一个更具体的关键词重新查，而不是同一个词反复查。换词只做一次，若仍相同会直接说明后以现有资料作答。

**Q16：会话列表里的数字角标是什么？**
该会话还有未确认的经验草稿（琥珀色数字）。与未读小圆点不同：当前会话也显示。点入该会话后用输入区「待确认 N 条」打开确认弹窗处理，确认或丢弃后角标随之减少消失。

**Q17：「执行态」和系统设置里的「执行模式」是什么关系？**
两层闸：执行态管「本会话允不允许动设备」——plan 态只读调查（写命令一律拒绝，AI 给出变更方案文本），执行态才真正执行；执行模式管「执行态里命令要不要逐条确认」——每次确认/智能/全自动三档。先切执行态，再按需调执行模式。

**Q18：昨天切了执行态，今天回来标题又变回 plan 态了？**
执行态是页面级短时授权：离开 AI 助手页或重启应用后自动回落 plan（防止开着执行态离开后遗忘）。重新需要时在检索设置面板再次开启（每次升级都要过二次确认）。

**Q19：自动压缩会丢我的聊天记录吗？**
不会。压缩只影响 AI 的上下文记忆——被压缩的旧消息退出 AI 的「工作记忆」（替换为检查点摘要），界面上的历史消息与检索不受影响；检查点卡点开还能看到摘要全文。

**Q20：token 状态栏全是「—」，手动压缩点不了？**
该会话是升级前创建的旧版会话，没有事件流统计数据。对话功能不受影响；新会话（或升级后继续使用的会话）正常显示。

**Q21：输入 @ 没有弹出候选？**
三种情况：没有名称匹配的设备/拓扑（零候选时刻意不弹层，避免空浮层干扰）；@ 处在邮箱地址或路径中段（如 a@b.com，防误触发）；候选数据未加载完成。先继续输入几个字试试过滤，或检查设备/拓扑名称。

**Q22：执行卡下面出现「⚠ 快照不符：未见预期变更」？**
命令本身执行成功了，但系统自动比对命令执行前后的设备配置快照，没有发现预期的变更。可能是命令实际未生效（如配置未提交）、变更不在可抓取的配置区，或断言本身与命令效果不符。核对设备实际状态后再决定是否重试。

**Q23：出现「已拦截的编造回复」黄色卡是什么？**
AI 那条回复声称完成了某些操作，但系统审计发现本轮没有对应执行记录——整条回复被拦截，系统同时质询 AI 要求重新作答。看跟随其后的修正回复即可；原文明细保留在卡内供核对。

**Q24：让 AI 生成报告文档后，去哪里找文件？**
消息流中的文档附件卡：「导出」另存到你指定的位置，或「打开文件夹」直接定位沙箱目录中的文件。注意沙箱快照有保留期（默认 7 天，见第 10 章沙箱文档存储），超期清理后可让 AI 重新生成；已导出的文件不受清理影响。

**Q25：重启应用后 AI 的多步任务停了？**
长任务执行停摆是设计行为（续行授权不持久化，AI 不会在你不在场时自行恢复执行）：切回该会话，消息流中的 goal 进度卡显示「等待续行」，点「继续」即从原进度续跑。会话列表的「任务进行中」徽标只表示任务在真正执行，停摆等待续行时不亮。

**Q26：重启前有个命令面板没处理，重启后去哪了？**
审批时限内的话面板会自动恢复——切回该会话即可继续「确认执行」或「拒绝执行」（时限从挂起时刻连续计算，不会因重启重新计时）。已超时的按「审批超时」自动拒绝收尾，消息流有系统提示条可查。

**Q27：多台设备巡检为什么看不到每台的完整命令输出？**
批量巡检由并行子代理执行，父会话只收每台设备的结构化摘要（异常 + 至多 3 行关键输出），子会话不提供查看入口——这是刻意设计：多台设备的原始输出会淹没对话上下文。需要某台设备的完整输出时，单独对那台设备提问即可。

**Q28：失败卡片尾部的「（追踪 xxxxxxxx）」是什么？**
8 位报障追踪短码。AI 页的失败信息（工具卡失败态、goal 卡受阻原因行、批量巡检失败/超时设备行）统一携带。报障时提供此号即可按号定位全链路日志；你也可以自己在 [第 9 章](./09-log-audit.md) 日志审计页的关键词框粘贴短码，直接查到对应的执行记录。

**Q29：AI 执行过的命令、发给大模型的报文去哪里查？**
都在 [第 9 章 日志审计](./09-log-audit.md)：「AI 助手执行日志」页签可按时间/状态/设备/关键词筛选（覆盖子代理巡检、MCP 工具、只读检索、沙箱等全部来源，成功失败都记）；越权命令的处理结果在「越权记录」视图；每次 AI 调用的完整请求与响应原文在执行日志详情末尾的「LLM 报文」折叠区与「LLM 报文」页签查看（默认记录、保留 30 天）。

## 本章术语

| 术语 | 解释 |
| --- | --- |
| 会话 | 一次完整对话线程，含消息、步骤卡与轨迹，可随时切回 |
| 未读小圆点 | 其他会话有新回复时的提示点，点入即清除 |
| 待确认经验数徽标 | 会话列表标题右侧的琥珀色数字角标，显示该会话待确认经验草稿数（当前会话也显示） |
| 任务进行中徽标 | 会话列表标题右侧的圆点+文字标记：该会话有正在执行的 AI 多步任务（停摆等待续行的不亮） |
| 设备上下文 | 本次对话选定的目标设备集及其能力档位 |
| 能力三档 | 设备按通道/MCP 配置派生的可执行/可调MCP/仅问答标注 |
| 执行态 | 会话级两档开关：plan 态（默认，只读调查，写命令硬拒）与执行态（经二次确认升级，可执行命令） |
| plan 态 | 只读调查档：AI 只执行只读命令、以文本输出变更方案 |
| 预取 | 回答前按问题档位自动检索注入资料（[预取] 前缀卡） |
| 补查 | 回答中途发现资料不足时追加检索（[补查] 前缀卡） |
| 强制补查 | AI 判定资料不足必发起补查的模式 |
| 智能补查 | 是否补查由 AI 自行判断的模式（未查源显示灰标签） |
| 换词重查 | 补查关键词与已查词相同时要求 AI 换词重查一次的机制（单次有界） |
| 检索设置 | 输入行首齿轮入口：预取开关 + 补查模式（全局持久）+ 执行态开关（会话级） |
| 分档 | 问题自动归类：故障排查/配置查询/知识问答/巡检执行 |
| 工具调用卡 | AI 每个动作的紧凑单行卡，可展开看输入输出 |
| goal 进度卡 | AI 多步任务的实时进度卡：目标/Round/步骤清单/状态词与「继续」续行按钮 |
| 等待续行 | 重启或会话恢复后任务停摆、等待用户点「继续」授权续行的 goal 状态 |
| 批量巡检组卡 | 多台设备派发子代理巡检的汇总卡：逐台状态/异常/关键输出与终态统计 |
| 子会话 | 批量巡检中每台设备绑定的独立子代理会话，不进会话列表，父会话组卡是唯一摘要面 |
| 核对结论行 | 执行卡上系统写入的配置快照比对结论（已核实/不符/无快照/后快照缺失四态） |
| 配置快照 | 写命令执行前后自动抓取的设备配置留档，用于核对变更是否生效 |
| 编造拦截 | AI 回复含执行断言但无执行记录时整体拦截并质询重答的机制 |
| 终轮对账警示条 | 回复底部「⚠ 本轮无命令执行记录（系统审计）」的系统对账提示 |
| 追踪短码 | 失败信息尾部的 8 位报障定位号「（追踪 xxxxxxxx）」，日志审计页关键词框粘贴即可直查（见第 9 章） |
| LLM 报文 | 每次 AI 调用发送给大模型的完整请求与返回的原始响应留痕（加密存储，保留 30 天，查询见第 9 章） |
| 纠偏递进 | 同设备连续失败 3 次提醒 AI 换方法、6 次终止的递进机制 |
| 熔断 | 连续失败过多后暂停执行进入冷却的保护机制 |
| 越权 | 命令目标超出对话设备集/发生跳转/MCP 参数敏感 |
| 审批面板 | 待确认命令出现时替换输入区的内联确认卡 |
| 审批超时 | 待确认命令超过时限（默认 10 分钟）未处理即自动拒绝的兜底 |
| 审批挂起恢复 | 重启后审批时限内的待确认面板自动恢复、时限连续计算不重置的机制 |
| 硬顶 | 自主任务的步数、连续失败熔断、失败冷却与上下文 Token 预算上限 |
| 硬停 | 用户手动停止任务后的诚实收尾提示 |
| 上下文压缩 | 把较早消息摘要为检查点、为上下文腾出空间的长会话管理机制 |

| 文档附件卡 | AI 生成 Word/Excel 报告后插入的卡，含导出与打开文件夹 |
| 经验起草 | AI 从会话提取候选经验的两阶段过程 |
| 采纳/丢弃 | 确认弹窗中对每条草稿的决策 |

| 质量门 | 草稿提交前按分类校验必填项（缺项标红禁交） |
